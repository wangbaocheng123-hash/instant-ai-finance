## 初步义务理解（非法律意见）

- 运行未修改程序、私人内部修改通常不等于向他人 convey；GPLv3 本身不是 AGPL，没有单纯网络交互触发源码提供的专门条款。
- 若分发原版或修改版源码/二进制，应保留许可证和通知，并按 GPLv3 提供对应源码；修改版需显著说明变更。
- 若把 GPL 代码复制、链接或组合成一个派生桌面程序并向他人分发，可能要求整个 covered work 在 GPLv3 下提供。
- 把 TrendRadar 作为独立进程/服务，通过文件、CLI 或 MCP 交互，可能降低组合风险，但“独立作品还是一个整体”取决于具体集成，不能由工程报告下法律结论。

## 对复用方式的影响

| 方式 | 初步判断 |
|---|---|
| 私人本地运行原版 | 一般可行，仍需遵守来源/内容授权 |
| Fork 后把整个客户端按 GPLv3 分发 | 技术上可行，前提是产品愿意接受 GPL 发布模型并履行义务 |
| 复制若干核心模块进非 GPL 正式产品 | 高风险，不建议 |
| 独立 GPL sidecar + 明确 IPC/MCP | 可进一步评估，需法务确认边界与分发包设计 |
| 只学习思想并独立重写 | 推荐，但需避免实质复制并保存设计来源记录 |
| 调用独立部署实例的 API | 可评估；还要核对数据源、服务条款和部署分发方式 |

## 未决许可证问题

1. 项目是否有官方 SPDX 声明或 “only/or-later” 解释。
2. 核心作者/贡献者版权通知和第三方代码清单。
3. `uv.lock` 所有传递依赖许可证兼容性。
4. HTML/图片/配置样例是否与代码同一许可证。
5. 默认 NewsNow API、各热点平台、RSS 文章和 Jina Reader 输出的内容授权。
6. “即时 AI”未来是否分发、商用、闭源，以及 TrendRadar 是否同包安装。

## 结论

许可证适合“接受 GPL 的整体 Fork”或“独立服务/设计参考”，不适合在未决策发布模型时直接嵌入正式 Windows 客户端。该结论是风险分级，不是法律意见。
