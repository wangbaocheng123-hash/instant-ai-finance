# ADR-0010：短周期即时热点雷达与自动淘汰

- 状态：`ACCEPTED`
- 日期：2026-08-28
- 决策者：用户明确纠正“没有长期数据、没有长期档案，只是即时跟踪热点事件的 APP”

## 背景

早期章程把 H 盘描述为长期个人投资资料库，现有实现也会永久累积 items、evidence、原始 Feed、缩略图、运行清单和备份。实际运行中 3748 条消息已产生 172610 条 evidence，查询需要跨全部证据关联；这既偏离用户目标，也会持续扩大数据库和文件占用。

## 决定

1. 产品定位改为“全球财经即时热点雷达”，不建立长期新闻档案、历史资料库或永久收藏。
2. 普通消息从发布时间或首次发现起保留 72 小时；重要度 70–84 保留 5 天；重要度 85 以上最多保留 7 天。7 天是绝对上限，临时置顶不能延长寿命。
3. 每次成功采集和服务启动时自动清理过期消息及其翻译、AI 任务、提醒、证据关系、原始抓取文件和缩略图；运行明细保留 7 天，数据库备份只保留最新 3 份。
4. 每个消息对同一来源只保留最新证据，并且最多保留 5 个来源证据。证据身份改用单条新闻的规范字段 hash，不再把整份 Feed hash 作为新闻版本身份。
5. 采集入口拒绝发布时间早于 7 天的内容，防止已淘汰旧闻被长 Feed 重新导入。
6. 热点由服务器从完整 72 小时窗口排序，客户端不再仅从最新 120 条中推导热点。查询先限制候选消息，再关联有限证据。
7. 搜索只覆盖当前生命周期窗口；CSV 长期导出入口退出公网 API。`收藏`改称`临时置顶`。
8. H 盘与 `/var/lib/instant-ai` 只是彼此独立的短周期运行根目录，不是正式档案或云备份。

## 影响

- 第一次启用会删除不符合生命周期的现有旧数据；实施前先生成预演并保留受同样“三份上限”约束的短期备份。
- 持续数周的战争、政策或产业主题不会保留同一张永久卡片；新阶段通过新的报道和事件卡片重新进入窗口。
- 运行时仍保存完成去重、可信判断和详情展示所需的短期证据，但这些技术数据不构成长期档案。
- ADR-0001、ADR-0004、ADR-0008 和 ADR-0009 中关于“正式档案、长期证据、永久收藏”的表述由本 ADR 替代；单用户、无账户、无自动交易、许可证和云端隔离边界不变。

## 实现证据

- 生命周期与文件清理：`product/instant_ai/retention.py`
- 单条新闻证据 hash 与旧闻拒收：`product/instant_ai/service.py`
- 完整 72 小时热点 API：`product/instant_ai/service.py`、`server.py`
- 临时置顶与当前证据文案：`client/instant-ai/src/instant-ai/InstantFinanceApp.ts`
- 自动化测试：`product/tests/test_core.py`
