# ADR-0028：博主单主人手机工作区与模型先生交互对齐

- 状态：`ACCEPTED`
- 日期：2026-08-31
- 决策者：产品所有者

## 背景

0.16.0 已把北京采集端传来的博主、作品、媒体与评论安全保存到新加坡独立资料域，但主人页面只展示传输摘要，不能直接播放已经接收的视频，也不能查看评论正文、视频原文或调用既有豆包识别流程。产品所有者明确要求博主作品的基础模板与模型先生一致，并在此基础上增加多博主切换和新增博主入口。

## 决定

1. 博主作品详情复用模型先生已经验证的手机交互：登录后本地视频播放、HTTP Range/HEAD、视频原文、识别结果、豆包识别、标题编辑和评论阅读；视频不自动播放。
2. 评论从已完成校验的 `blogger-comments/v1` gzip NDJSON 读取。页面只返回重新编号、不可逆线程键、作者显示名、正文、时间、点赞、回复、作者回复和作者点赞标记，不返回来源评论 ID、账号 ID、主页、路径、原始 JSON 或机器身份。
3. 主人编辑的标题、正式视频原文和识别结果写入 Git 外 `/var/lib/instant-ai/blogger-agent/database/blogger_owner.db`。它不修改北京传输清单和 artifact 账本，不写入财经新闻库或模型先生资料域，也不进入 Git。
4. 豆包按钮只有在主人点击并确认按时长计费后才调用；进入页面、接收 complete、查看视频或评论均不得自动触发 ASR。服务器缺少 `ffmpeg`、凭据、额度、权限或网络时返回脱敏错误并保持已接收资料不变。
5. 博主页面增加横向博主切换条和“新增博主”。新增操作只打开北京采集端唯一根入口 `https://collector.amuyeye.com/`；旧 `/collector/` 入口由北京反向代理跳转到根路径。北京继续作为博主配置与采集事实源；新加坡不建立反向控制北京的接口。
6. 新接口继续受即时 AI 单主人登录保护。媒体文件只通过应用私有接口读取，Caddy 不公开 artifact 目录；标题和原文写入还必须带现有 `X-Instant-AI` 同源写请求头。
7. 版本升级为 0.17.0。正式发布仍遵守 ADR-0019 和项目永久规则，只有所有者明确要求“正式发布”后才调用受限发布器。

## 结果与回滚

- 北京采集器、签名传输协议、即时财经、模型先生和时变罗盘不因本决定改变。
- 删除或回退 0.17.0 代码不会删除 Git 外媒体、评论或主人内容数据库；回滚后 0.16.0 仍可显示传输摘要。
- 现场豆包新转写仍受 `ffmpeg` 安装与可能费用的单独批准约束；已有视频、评论和主人保存原文不受该阻塞影响。
