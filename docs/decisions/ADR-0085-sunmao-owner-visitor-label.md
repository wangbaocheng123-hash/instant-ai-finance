# ADR-0085：榫卯社区管理员浏览标记为“主理人”

- 状态：ACCEPTED
- 日期：2026-11-10

## 背景

社区后台原本只把管理登录用于保护统计接口。公开页面的访问统计始终按浏览器匿名标识显示为“木友-XXXXXX”，因此所有者本人登录后台后，仍无法在最近访客中区分自己的公开页面浏览记录。

## 备选项

1. 把所有后台登录都记成独立的访问记录：会把管理操作混入公开栏目统计，且不能识别所有者登录前已经产生的浏览记录。
2. 新建用户、角色或会员表：超出单主人边界，并为一个显示名称引入不必要的身份数据。
3. 成功登录后只关联当前匿名浏览器摘要：沿用既有统计身份，既能改名已有记录，也不改变公开访问统计口径。

## 决定

只有单主人管理账号成功登录时，服务器才把当前浏览器的一年期匿名访客标识登记为“主理人”。已有访客记录立即改名；以后同一浏览器提交的公开页面浏览继续显示“主理人”。如果浏览器 Cookie 丢失但同源本地备份仍在，后台登录会沿用该标识；清除全部站点数据或更换设备后，需要再次成功登录后台才能标记新的浏览器。

数据库只新增匿名标识摘要与关联时间，不保存管理账号、密码、IP、完整 User-Agent 或原始访客令牌。错误账号、错误密码和未登录请求不能建立“主理人”关联。后台页面本身仍不计作交流区、尺寸型或榫卯108道的公开浏览；本决定也不建立会员、用户表、角色或多人权限体系。

## 理由

第三项直接满足所有者区分本人浏览的需求，并继续遵守社区匿名统计和单主人管理边界。服务器以已验证的管理登录作为唯一授权点，浏览器 Cookie 优先、本地同源备份仅在 Cookie 缺失时恢复匿名标识；两者都不需要读取或保存真实身份资料。

## 影响

管理后台的最近访客列表可以直接区分“主理人”和普通“木友”编号。退出后台不会抹掉既有浏览归属；社区服务重启会按原规则结束内存中的后台会话，但持久化的匿名主理人关联保留。

同一个所有者可在多个成功登录过的浏览器中显示为“主理人”。清除全部站点数据或更换设备会产生新的匿名标识，必须再次成功登录后台才能关联。若以后撤销某台设备的显示归属，需要另行设计精确解除机制，不能通过猜测摘要或批量清库处理。

## 证据

0.3.11新增成功登录前后、未来访问及错误账号不能标记的回归覆盖；完整48项社区测试、前后台 JavaScript 语法检查、Python 编译和差异检查通过。提交`b4ce7ecdebbcb0233f49d0e5d75d50bc3b77dbae`已通过社区专用发布器正式上线；中文公网版本、后台保护、匿名摘要表及并列服务隔离检查通过。真实所有者浏览器的显示仍以本人成功登录后的确认结果为准。

## 替代与撤销关系

本决定扩展既有匿名访问统计，不替代其他ADR。撤销时应删除登录关联行为并通过明确迁移处理`analytics_owner_visitors`，不得让旧摘要映射静默改变为账号或会员数据。
