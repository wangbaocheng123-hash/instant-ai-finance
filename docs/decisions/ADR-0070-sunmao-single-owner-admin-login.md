# ADR-0070：榫卯社区后台使用单主人账号与密码

- 状态：`ACCEPTED / LIVE`
- 日期：2026-10-15
- 决策者：产品所有者

## 背景

社区0.3.3已把管理后台入口显示在公开首页，但后台登录表单只有密码字段。产品所有者提供了一组管理账号和密码，要求后台使用这组凭据登录。社区后台仍只服务一个所有者，不需要注册、用户表、角色系统或多账号管理。

## 备选项

1. 继续只校验密码：实现最少，但不符合所有者明确给出的账号与密码登录方式。
2. 建立管理员用户表：可以扩展多个账号，但会无端引入多用户、迁移和管理界面。
3. 使用Git外单主人账号文件与密码摘要文件：满足当前登录要求，同时保持最小身份边界。

## 决定

1. `/admin/`登录表单和`/api/admin/login`同时要求`username`与`password`，错误时统一返回`invalid_credentials`，不分别透露账号或密码是否正确。
2. 只保留一个主人账号，不建立用户表、注册、找回密码、个人资料、角色或权限系统。
3. 账号保存在Git外`/var/lib/sunmao-community/admin-username`，密码只保存PBKDF2-SHA256摘要于`/var/lib/sunmao-community/admin-password.hash`；两者均为`sunmaocommunity:sunmaocommunity 0600`。
4. 账号和密码必须同时匹配才创建内存后台会话；继续使用同源校验、登录限流、HttpOnly、SameSite=Strict及HTTPS下Secure Cookie。服务重启会清空旧会话。
5. 凭据值不得进入Git、日志、部署元数据、状态账本或验收输出。

## 理由与影响

该方案实现所有者要求的账号加密码登录，同时不扩大为社区用户体系。新增账号文件属于现有社区Git外数据目录，不改变数据库、发布分支、进程或端口；回滚应用版本时新文件可以保留，旧版只读取密码摘要。

## 证据

- 本地与生产隔离测试各26项通过，包含正确账号登录、错误账号拒绝、后台鉴权和部署隔离契约。
- 北京release为`51e29ca218cd2954addfa9edcdfdd11dd93e4b8c` / `0.3.4`，公网登录页同时显示账号与密码字段；未登录统计仍为401，使用所有者提供的凭据真实登录200，认证后统计接口200。
- 两个凭据文件的属主与权限均通过只读元数据核对；采集器与模型下载器InvocationID前后不变。

## 替代与撤销

本决定只替代社区后台“仅密码登录”的0.3.2—0.3.3实现，不改变ADR-0067、ADR-0068规定的社区独立运行、Git外数据和社区专用发布边界。
