# ADR-0002：R0 推荐“薄型领域核心 + 独立服务”组合

- 状态：`PROPOSED`
- 日期：2026-08-23
- 决策者：待用户 D0 批准

## 背景

六仓静态源码考古表明，没有一个项目同时具备授权采集、网页变化、结构化金融数据、长期证据、跨源去重、领域实体/事件、可审计 AI、Windows 阅读器和可接受的统一许可证边界。直接选择完整上游作为主底座会带来数据模型缺口、深度 Fork 和许可证风险。

## 建议决策

采用自有薄型领域核心，只实现六仓均未完整提供的证据契约、长期数据模型、跨源幂等、财经实体/事件、规则评分、本地 API 与通知 outbox；成熟能力通过独立服务/API 复用：

- RSSHub：Feed 转换；
- changedetection.io：官方网页变化；
- OpenBB：结构化金融数据；
- TrendRadar：保留为热点/规则/通知候选服务或条件 Fork；
- Folo：只作 UI 参考；
- n8n：MVP 后用户可选工作流 sidecar。

正式业务数据统一落在 `H:\即时AI文件库`，上游源码、进程、许可证和缓存保持隔离。

客户端和本地 API 按单机单用户运行，不引入账户、登录、用户资料、团队、角色或权限管理层。

## 理由

- 最大化复用各项目成熟边界，同时避免混合源码。
- 让来源、证据、实体/事件和规则解释权留在即时 AI。
- 上游服务可独立升级、替换或禁用。
- 降低但不消除 GPL/AGPL/SUL 组合风险。

## 代价

- 需要自行设计最小领域 schema、adapter contract 和本地 API。
- Windows 需要管理多个可选本地进程。
- 首次可见功能少于直接 Fork TrendRadar 或用 n8n 拼装原型。

## 不包含的决定

本 ADR 不锁定 Tauri/Electron/PySide6，不锁定最终数据库，也不批准正式产品开发。个人单机、无账户且当前不分发的边界由 ADR-0003 固定；未来若改变分发场景需新 ADR。

## 采纳条件

只有用户在 D0 明确批准后，状态才能改为 `ACCEPTED`。若用户选择接受 GPL 并以 TrendRadar 为主底座，应新建替代 ADR，而不是静默改写本记录。
