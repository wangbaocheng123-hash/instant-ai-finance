# ADR-0039：普通博主自动处理采用开启边界、到达补偿与分步可观测状态

- 日期：2026-09-07
- 状态：`ACCEPTED_AND_LIVE`
- 正式版本：0.21.1（功能提交 `02f1348`）
- 决策者：产品所有者

## 背景

普通博主 0.21.0 队列只在传输 `complete` 回调发生时检查自动开关。主人开启开关后，开启前已经完成的作品不会入队；服务短暂重启、数据库锁或回调丢失也没有补偿路径。客户端又只在主人主动点击时读取一次队列状态，不随后台阶段刷新，并以不透明作品摘要显示任务。结果是豆包可能没有收到任务，或者后台已经变化但手机页面看起来仍然“没有反应”。

所有者要求：自动处理可手动开启和关闭；开启后新视频完成传输即自动识别原文并提炼 AI 关键词；逐条手动操作只作漏项修复；页面应明确显示当前作品、排队、视频原文、关键词、完成或异常状态。

## 决定

1. 自动开关继续默认关闭，并持久保存 `enabled_since`。从关闭切到开启时写入新的开启边界；关闭期间到达的作品不会在下次开启时自动补做。升级旧队列若原来处于开启状态，因为无法证明旧开启时间，边界从升级时刻开始，不据猜测回扫历史。
2. 传输完成回调仍是最快入口。后台执行器每三秒再以 `max(enabled_since, last_reconciled-1秒)` 查询已完成、current、accepted、普通博主且有已验证 MP4 的到达记录。队列以作品键和媒体摘要去重，因此一秒重叠、回调重放、进程重启或短暂锁冲突不会重复创建付费任务。
3. 补偿扫描只覆盖本次开启后的完成时间，不建立历史批处理。已有原文或关键词继续复用且不覆盖。单条视频仍限制 20 分钟、普通博主队列每日最多 20 次模型调用，与模型先生及手动识别共用提供器锁；结果不明确的付费调用仍不自动重试。
4. 为开启前作品或其他个别漏项增加主人认证、CSRF 与费用确认保护的单条 `process` 操作。它一次排队完成缺少的视频原文和 AI 关键词，复用同一去重键；已有内容不重做。主人明确重试或补做会把对应任务转为手动任务，即使全局自动开关关闭也可继续，但 `review` 仍需单独核对后重试。
5. 处理状态接口增加安全作品标题、博主显示名、自动/手动来源、执行器存活、最近补偿扫描、全量状态计数，以及“视频原文”和“AI 关键词”两个步骤。接口不返回原文、模型响应、路径、密钥或原始错误。
6. 博主页面初次进入即读取开关，不再要求先点“查看状态”；选中博主时每四秒只轮询轻量队列状态。任务完成后刷新当前作品摘要和详情；输入框或文本区正在编辑时不替换草稿，待失焦后再更新。作品详情提供单条“一键补做原文 + AI关键词”。
7. 页面保留明确的“手动开启”“手动关闭”；连续三次异常暂停时同时允许关闭或在核对后恢复。最近任务按真实标题和博主展示两个步骤及各自状态，不再只显示作品哈希。

## 影响与兼容

- 队列表只无损增加设置列；现有任务、调用计数和主人资料不删除、不覆盖。
- 新扫描是本地只读 SQLite 查询，不调用外网；只有去重后的队列任务进入既有豆包付费阶段。
- 0.21.1 不修改北京采集器、模型先生、统一 MCP、财经采集或时变罗盘。
- 本次开发与测试使用合成视频和模拟提供器，不开启生产开关、不读取生产资料或凭据，也不产生真实模型费用。

## 验收与回滚

- 回归必须证明开启前作品不会自动入队，开启后已验证视频在回调丢失时能被补偿扫描发现，重复扫描只保留一个任务。
- 回归必须证明全局开关关闭时，主人确认的单条旧作品补做仍能串行完成原文和关键词，并显示两个步骤完成。
- API 回归必须覆盖主人登录、CSRF、费用确认和单条处理路由；前端契约必须覆盖手动开关、四秒刷新、一键补做和分步状态。
- 回滚应用代码不会删除新增设置列或队列记录。先手动关闭自动开关；任何 `review` 任务都先核对提供器调用记录，不盲目重试。
