# ADR-0096：北京采集器零数量与分钟级评论窗口

- 日期：2026-11-28
- 状态：IMPLEMENTED / TESTED / RELEASE_PENDING
- 目标版本：北京博主采集器1.3.2
- 授权：所有者要求修复单链接下载时数量无法填0、评论跟踪时长不能按分钟设置，并明确“完善结束以后直接发布即可”。本句已授权同一任务中的正式北京发布，不再要求固定口令逐字复述。

## 行为及兼容

普通博主的`history_limit`允许0～1000。0关闭主页按数量抓取，主按钮进入链接输入；无链接时界面和HTTP触发均拒绝批量运行。执行器在真正打开主页前再次核对，防止排队后设置改为0时仍扫描。指定链接仍复用原单作品解析、下载、评论和签名发送，与数量字段独立；大杂烩原链接模式保持。

`creator_comment_tracking_minutes`作为分钟精度事实源，范围1～43200（30天），UI及API使用`comment_tracking_minutes`。旧配置仅有`creator_comment_tracking_hours`时等值乘60；规范化及保存同时保留派生小时字段，旧客户端提交小时仍受支持，新分钟字段优先。Settings、博主注册表、运行状态及评论窗口判断使用同一转换函数，避免15分钟被整数小时截断、重启后恢复成默认值。旧大杂烩运行key/UUID与原评论设置保留。

窗口按既有作品发布时间计算，不是轮询间隔。首次下载、明确指定单视频或手动补抓继续获取当前公开评论；其他窗口内刷新仍受已有刷新间隔约束。保持仅手动采集，不新增自动评论调度、Git轮询或付费识别动作。无数据库迁移，无来源、媒体或签名协议变化。

## 发布及回滚

按所有者本次明确授权，提交并推送main，使用既有脚本安全快进beijing-production，再经beijing-admin调用一次root固定套件发布器。模型子树未变化，按现有tree门禁跳过；上线后验证公网精确版本、运行摘要及认证，Git timer保持disabled/inactive。即时AI0.36.0候选不在本次发布范围。

回滚用新的revert提交继续前进。原数据不删除；旧程序对0及不足1小时的值会重新应用旧下限，因此回滚不能宣称仍保有分钟精度。正式结果在实际完成后追加。
