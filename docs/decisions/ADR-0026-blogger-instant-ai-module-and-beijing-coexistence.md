# ADR-0026：博主模块融入即时 AI 与北京双服务并存

- 状态：`ACCEPTED`
- 日期：2026-08-31
- 决策者：产品所有者

## 背景

早期方案把“博主智能体”描述成同时覆盖北京采集和新加坡智能处理的一套独立源码系统，并考虑由北京采集能力替代原模型下载器。所有者随后明确纠正：新加坡即时 AI 和其 Git 仓库、AI 能力、主人登录及发布链路都已经存在；北京原模型下载器也应继续保留，不做清理或迁移。

## 决定

1. 新加坡博主页面、主人只读 API、机器接收路由和后续智能处理器全部进入现有 `instant-ai-finance` 仓库，随即时 AI 同一版本构建和发布。新加坡服务器不再建立、克隆或连接第二个“博主智能体”应用仓库。
2. 博主入口紧邻模型先生右侧：桌面导航、手机底栏和单页内容顺序均为“重点 → 模型先生 → 博主”。博主仍是独立功能入口，不与模型先生页面合并。
3. 复用的是即时 AI 已有的主人登录、HTTPS、服务进程和未来经批准的 AI 适配能力；博主数据继续保存在 `/var/lib/instant-ai/blogger-agent`，不得写入财经新闻 `instant_ai.db` 或 `/var/lib/instant-ai/model-mr`。
4. 北京服务器保留现有模型下载器，不删除、不清理、不接管其代码或运行数据；另行部署一套博主采集服务。两者可以共享服务器，但使用独立 service、配置、数据目录、日志和资源限制。
5. 北京博主采集服务继续通过 ADR-0024/0025 的签名 HTTPS 协议主动推送新加坡。模型下载器不自动成为协议发送端，也不要求为本次接入迁移其历史数据。
6. 新加坡源码检查点使用即时 AI 现有 Git 远程。北京采集端可以保留独立源码检查点，但它不是新加坡运行时依赖，也不会让即时 AI 服务器再维护一份应用仓库。
7. 本决定不授权正式发布、真实数据传输、付费转写、安装 `ffmpeg`、读取密钥或修改时变罗盘。正式发布仍需所有者明确说“正式发布”。

## 结果与回滚

- 即时 AI 0.16.0 以一个应用版本交付博主入口和接收能力；生产 0.15.2 在正式发布前保持不变。
- 北京任一服务故障都不应删除或覆盖另一服务的数据。博主采集服务可独立停止，原模型下载器继续运行。
- 若博主模块需回滚，只回退即时 AI 应用版本并关闭机器接收配置；Git 外博主账本和媒体保持原样，不触碰模型先生、财经新闻或时变罗盘数据。
