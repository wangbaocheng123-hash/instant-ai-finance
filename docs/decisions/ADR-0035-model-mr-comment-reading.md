# ADR-0035：模型先生评论阅读顺序与作者/评股呈现

- 日期：2026-09-04
- 状态：开发验收完成，未正式发布
- 基线：云端干净 main `7aaa527`，延续 ADR-0023 和 ADR-0034

## 用户要求

模型先生评论需要醒目的红色作者回复、作者点赞标记，优先展示高赞前十和内容较完整的回复；评股需要展示排名和关联评论，手机可点击、按需加载。不得重新采集或隐式调用 AI。

## 决策

1. 使用来源已保存的 `author`、`author_comment`、`author_reply` kind 识别作者。作者点赞使用独立 `author_liked` 布尔字段。昵称相同不构成身份凭据，缺少来源标记不猜测、不回写。
2. 评论以线程呈现，原问题与作者回复保持关联；即使缺少根评论，也保留已有孤立回复。作者回复先展示，其次作者点赞回复，然后按点赞数排列。先渲染 6 条回复，展开后每批增加 30 条。
3. 粉丝排行排除作者根评论及纯表情、简单重复话语。正点赞线程按根评论点赞数、回复数、有效字数取前 10，不足 10 不用零点赞补足。其余线程优先有效正文至少 20 字，再按有效字数（上限 500）、回复数、点赞数排序，同分保留来源顺序。先渲染 60 组，可继续加载。
4. 上述是确定性的阅读辅助规则，不是语义模型打分，也不保证内容真实或观点正确。界面明确说明规则，原评论不删改。关键词/投资思路内仍复用同一详情播放器。
5. 评股使用已保存的本地证券名称表识别报告，不新抓取行情、不调用 AI、不重新写数据。按去重评论数、提及次数、证券代码排序，最多展示 20 项，并分别显示粉丝和作者评论计数。
6. 股票行展开才生成关联评论 DOM，按报告中的评论编号连接到已有线程，保留原问题上下文；首批 20 组，再按按钮加载。上下文中未提到股票的内容不计入该股热度。无正文时明确展示缺失状态；只有摘录时标为已保存摘录。无法确定的简称单列且不计入股票排名。

## 边界

- 仅修改即时 AI 模型先生显示层和纯排序逻辑，不改变身份、主人认证、MCP、采集、付费确认或持仓/基金/交易数据。
- 不把真实评论、截图、导出资料或预览目录提交到 Git。新增测试全部使用合成数据。
- 按需渲染优化 DOM；单作品详情仍沿用现有一次读取评论契约，不声称网络层已经分页。
- 本候选不正式发布。后续发布须主人明确授权，通过已有受限发布器；既有元数据迁移仍应针对最新生产状态重新合并，不用旧预览覆盖生产。

## 验收

- 6 项纯逻辑单测：身份来源、低信息过滤、前十与长回复分组、少于十条、稳定并列、上下文/孤立回复。
- 390px 手机触控和 1280px 桌面：红色作者标识、点赞标记、原问题、回复分批、高赞前十、长回复优先、评股排序/展开/缺失正文/待核对状态、无横向溢出、无采集或 AI 请求。
- 同尺寸原关键词/分类浏览器回归、4 项现有前端契约、114 项 Python 回归和 TypeScript/Vite 构建通过。

## 历史标记核对与验收副本

真实 1,419 条评论验收发现：截图中 595 赞的作者主评论，在本地与云端底层都被保存为 `user_comment`，旧本地页面依赖昵称显示“作者”。不能把所有同名读者无条件升级为作者。

依据主人本轮截图，对同一作品内作者名称、完整正文、发布时间和点赞数严格核对，仅在 Git 外新验收副本将这一条 `kind` 改成 `author_comment`。其他 409 个文件逐个 SHA-256 相同，该详情除这一字段外 JSON 值完全相同。副本为 `/home/compassdev/instant-ai-previews/model-comments-20260904-v3`，内有独立确认审计；未写生产、未改变本地源资料或重新采集。真实手机/桌面预览确认此条红色作者标记、另一条作者回复及作者点赞标记可见。

该单条确认以主人截图为依据，不能扩展成全库昵称推断。以后正式发布须在最新资料上重做精确匹配并应用这一确认，不能整体覆盖此旧副本；其余缺乏明确身份标记的同名评论仍不自动认定为作者。
