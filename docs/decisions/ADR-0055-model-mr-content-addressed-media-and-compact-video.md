# ADR-0055：模型先生传输媒体全局去重与新视频轻量化

- 日期：2026-09-20
- 状态：`ACCEPTED / IMPLEMENTED / RELEASED`
- 目标版本：即时 AI `0.23.1`；北京模型下载器 `0.10.2+git.compact-video`
- 决策者：产品所有者明确要求执行磁盘治理，并把模型先生视频分辨率缩小一倍

## 背景与现场证据

新加坡根云盘约 48.85 GiB，已用约 45.16 GiB，普通程序只剩约 1.48 GiB。
北京已投递账本与新加坡保存契约交叉核对后确认：模型先生只有 46 个不同视频，
却因评论变化形成 3,216 个修订；旧接收端按 transfer 目录再次保存完整 MP4，
累计约 26.63 GiB，而不同视频本身只有约 0.38 GiB。每条作品平均约 70 个修订，
最多 188 个。主要容量问题是同一视频的物理副本，不是正式资料库中的不同视频。

北京最近十个视频的现场只读探针显示，主要尺寸为 720×1280，少数为
576×1024；现有新加坡历史主人视频库已长期使用约 360p 的 H.264/AAC MP4。

## 决定

1. 新加坡传输接收端把媒体改为内容寻址保存：
   `artifacts/objects/media/<sha256>.<ext>`。相同 SHA-256、长度和 MIME 永远只保存
   一个物理对象；评论包使用独立的 `objects/comments` 命名空间。
2. 新修订清单到达后，接收端先重新校验已有内容对象或旧版已验证 artifact。
   校验成功即把新修订标为已收到，并从 `missing_artifacts` 中移除。因此评论变化
   仍保留完整可审计清单，但北京不再重传相同视频。
3. 服务启动时执行幂等压缩迁移：先为每个摘要建立并完整复核内容对象，再在 SQLite
   事务中把所有对应修订改指向该对象，最后只删除数据库已无引用、且路径严格匹配
   旧版自动生成 transfer 目录的普通文件。优先使用同文件系统硬链接，失败才流式复制；
   任一步中断后，下次启动可以继续。作品、修订、处理队列和审计账本均不删除。
4. 历史唯一评论包体积很小，不为搬动单份评论制造数千次磁盘事务；只有重复评论包
   和全部媒体进入启动压缩。以后新评论包直接进入内容寻址目录。
5. 模型先生正式资料库继续保存一份独立可播放视频；本迁移只清除传输暂存历史中的
   重复字节，不删除正式视频、标题、原文、关键词、评论、解读或投资思路。
6. 北京模型下载器从下一条新视频开始，在写入正式库前统一生成手机轻量 MP4：
   通常把长宽各缩小约一半（720×1280 → 360×640，576×1024 → 288×512），
   宽度最低 240 像素并保持比例；编码固定为 H.264 `libx264`、`yuv420p`、AAC 64k、
   双声道和 `+faststart`。下载到的有声流和分离音频流都走同一输出契约。
7. 既有北京视频和新加坡正式主人视频不在服务启动时批量转码或覆盖。这样避免一次性
   改写业务资料、重新触发 46 条到达任务或降低已经保存的封面文字质量；轻量化只作用于
   后续新下载视频。

## 安全与容量结果

- 内容复用必须以长度、完整 SHA-256、普通文件和安全父链检查为前提，不能只相信文件名。
- 数据库先改指向、旧路径后删除；删除前再次确认引用数为零。未知文件、链接、异常目录
  和无法验证的内容一律保留并计入错误，不做猜测性清理。
- 首次正式启动实际释放 28,234,240,000 字节（26.30 GiB）；根盘使用率从 97% 降至
  41%，可用空间从约 1.5 GiB 增至约 28 GiB。
- 本次治理不清理 Codex 会话、Swap、正式模型先生视频、时变罗盘资料或系统软件。

## 验收与发布门禁

- 合成两次作品修订必须证明：第二次清单只要求上传新评论包，两个修订引用同一个媒体路径，
  不上传第二份视频也能完成 transfer。
- 旧 transfer 目录模拟必须证明：重启后账本行全部保留并改指向内容对象，只有无引用旧副本
  被删除；再次启动无重复迁移。
- 北京纯函数测试固定半尺寸滤镜、H.264/AAC、`yuv420p`、64k 音频和快启参数；真实
  ffmpeg 回归生成带声 720×1280 输入并验证输出为 360×640、H.264/AAC、`yuv420p`，
  北京现场同时确认 `libx264` 可用。
- 即时 AI 与北京代码必须分别完成完整回归。正式发布前仍遵守既有即时 AI 与
  `beijing-production` 双重发布门禁；候选测试不得直接修改生产媒体。

## 正式发布结果

- 新加坡固定发布器把生产从 `50c8c2c` 安全快进到 `d8d3a5a`，207 项服务器回归通过；
  公网健康、Service Worker、服务状态与未登录私有媒体 401 均通过。
- `beijing-production` 与北京模型 current 均为 `d8d3a5a`；统一发布器完成 25 项隔离测试，
  版本为 `0.10.2+git.compact-video`，三个业务服务 active，发布 timer disabled/inactive。
- 发布后真实主页扫描 10162 成功但没有新作品，因此没有为验收重写历史视频。下一条自然
  新视频到达后再核对真实尺寸、编码、快启、手机播放和签名传输。

## 回滚

回滚代码不会把已合并的内容对象重新复制成每修订一份。所有账本行仍指向合法的
`artifacts/` 内部路径，旧版本的安全路径读取逻辑可以继续读取；如需再迁移布局，必须另建
显式、可验证的迁移，不允许根据目录名重造业务资料。
