# ADR-0061：财经发现源限流退避与 CNBC 直连补强

- 日期：2026-10-11
- 状态：`ACCEPTED / IMPLEMENTED / RELEASE AUTHORIZED`
- 目标版本：即时 AI `0.27.1`
- 决策者：产品所有者
- 关系：扩展 ADR-0005 的财经发现来源与 ADR-0010 的短周期运行数据；不改变单主人、无自动交易、无正文归档及模型先生链路。

## 背景与现场证据

所有者发现“最新消息”和“华尔街”长期停留在旧的市政债券条目。只读排查确认前端每 60 秒刷新，API 也返回 `no-store`，不是浏览器缓存或必须另设定时任务。生产服务保持 active，五分钟后台调度仍在运行；真正故障是 11 条 Google News 查询源都按五分钟周期集中请求，相当于最高每小时 132 次同一上游访问。

2026-10-11 11:54（北京时间）从生产主机复测，`global-financial-wire`、`wall-street-wire`、`global-bank-research`、`ai-big-tech-wire` 和 `nasdaq-investor-education` 均返回 HTTP 429；同期独立官方/直连来源仍返回 HTTP 200。旧实现只记录错误，五分钟后又同时重试，没有按来源保存下次请求时间和失败次数，因此会持续撞限流并让依赖 Google 的栏目缺少新条目。

## 决定

1. 五分钟服务调度保持不变，用户无需建立第二个定时任务。调度器只选择当前到期的来源；独立官方/直连源继续按各自周期采集。
2. `news.google.com` 统一视为共享上游组。每次五分钟调度最多请求其中一个到期源，并在各查询源之间轮换；一次成功或 304 后，单条 Google 查询至少一小时后才再次到期。
3. schema 13 在 Git 外 `sources` 表增加 `last_attempt_at`、`next_fetch_at` 和 `failure_count`。HTTP 429 从一小时开始按 1、2、4、6 小时退避并封顶六小时；其他异常从该来源正常周期开始指数退避。成功后清零失败次数，手动重新启用来源时使其立即到期。
4. 新增两条 CNBC 公开 RSS 直连：`cnbc-top-news` 与 `cnbc-finance`，每十分钟采集一次。它们分别补充全球财经以及全球财经/华尔街栏目；只保存标题、日期、原站链接和发布方，不抓取或冒充文章正文，可信度固定为 3/5。
5. 来源状态页把 429 显示为“上游限流，自动退避”，其他错误显示为“异常，自动重试”，并展示下次尝试时间；原始错误只放在悬停提示，不把限流误报成整个系统停止。
6. 运行清单增加本轮实际尝试和因计划/退避延后的来源数量。旧条目继续依 ADR-0010 自动淘汰；不删除历史资料、不修改罗盘、北京采集器、模型先生、Web Push门槛或任何交易功能。

## 验证与发布门禁

- 隔离真实网络验证只启用两条 CNBC 与两条 Google 来源：共四源，本轮尝试三源、延后一源；取得 60 条、入库 44 条，CNBC 两源均成功且安排十分钟后再取，Google 一源 429 后安排一小时退避，另一源没有被同时请求。
- 样本含 CNBC 在 2026-10-10 发布的微软 AI 与摩根大通固定收益等当日条目，证明“最新消息/华尔街”可由非 Google 单点路径继续前进；这只证明公开 Feed 可用，不冒充生产主人页面已经验收。
- 新增轮换、持久调度、schema 迁移、429 退避上限和 CNBC 权利边界回归；完整 254 项 Python 测试、Python 编译、前端契约、TypeScript/Vite 0.27.1 构建与静态资源同步通过。
- 产品所有者已于 2026-10-11 明确要求“修复并发布”。正式发布结果在固定发布器完成并通过公网健康检查后补记，不能把本地测试冒充生产上线。

## 回滚

回退应用代码即可停止新的分组调度和两条 CNBC 来源；schema 13 的附加列与已有短周期条目保留，不做破坏性降级。恢复旧版本不会删除财经条目、主人 Web Push 订阅、模型先生资料或罗盘数据。

## 实现位置

- `product/instant_ai/database.py`：两条 CNBC 默认来源与 schema 13 调度字段。
- `product/instant_ai/service.py`：到期选择、Google 共享上游轮换、成功间隔与失败退避。
- `client/instant-ai/src/instant-ai/InstantFinanceApp.ts`：来源健康和下次尝试时间显示。
- `product/tests/test_source_scheduling.py`、`test_core.py`：调度、迁移、退避和来源契约。
