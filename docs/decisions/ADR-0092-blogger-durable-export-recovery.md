# ADR-0092：北京本地发送待办持久恢复与旧大杂烩身份保留

- 日期：2026-11-22。
- 状态：IMPLEMENTED / TESTED / MAIN_CANDIDATE；未正式发布。
- 依据：所有者在只读根因排查后要求“补齐就行了修复它”。本轮完成修复与测试；正式分支继续遵守AGENTS.md及北京发布手册的明确发布口令。

## 决定

1. 大杂烩1.3.0候选继续使用固定platform_user_id与link_only。已有同名库同时保留creator_uuid和旧runtime key，不迁移或丢弃原state.json；miscellaneous作为规范别名，所有管理入口解析到同一现有记录和服务。新建库仍用既定固定身份，不创建第二个同名库。
2. 每次内容完成回调之前先持久化发送意图，成功入outbox后保存transfer_id并清除pending。新增content_ready_retry_version=1及失败次数/下次时间，失败退避最高30分钟，没有次数上限丢弃。只重试已保存的本地内容，不调用抖音、下载器、评论、识别或模型。
3. 复用北京既有sender循环，在发送前恢复最多10条待办；共享原串行执行锁，以非阻塞方式让位正在采集的任务。恢复失败与已入队发送隔离，不新增timer，不启用Git轮询。原“重试传输”入口也先补办未入队项，再处理现有网络重试。
4. 自动迁移仅覆盖本次确诊的大杂烩旧pending；其他普通博主的旧无版本pending作为legacy_review展示，可能已有较新送达修订，不能盲目重放。今后所有博主的新发送意图使用同一持久恢复机制。来源作品ID、作者与现有媒体文件须核对；错库或缺文件保留待办，不补采、不生成空媒体成功。
5. 导出器对同节点/creator_uuid/平台/作品的最新outbox快照做规范内容比较，排除协议序号、修订号与采集器版本。相同证据复用原transfer_id和状态，恢复崩溃窗口不产生重复修订；实质新证据仍创建新修订。dead_letter需核对，不通过新建相同修订绕过。
6. 页面区分采集完成、待打包、待发送、媒体上传、等待确认及已送达；已送达仍只取签名完成回执。后台摘要纳入发送前失败，隐藏原始错误/路径；旧资料待核对独立显示，不误标为新采集失败。PWA壳升至v7以更新提示与按钮。

## 边界与验收

复用原Git外配置、state.json、SQLite outbox、HTTPS/HMAC、媒体摘要及新加坡完成回调，数据库/数据位置、单主人和原收费审批边界保持。新加坡没有反向轮询、代采或新报告接口。模型下载器、社区、域名、罗盘及发布基础设施不在本次修改范围。

250项完整北京采集器测试通过，无跳过，新增恢复/重启幂等/证据更新/退避/人工force/错库/缺媒体/忙锁/旧资料隔离/死信/入队后状态写失败，以及摘要/补办入口/发送器故障隔离检查；JS语法、PWA契约和Git差异通过。生产当前仍1.2.0，真实补发、签名回执及新加坡显示必须在明确发布后单独验收。

回滚保留新增意图字段、旧runtime key、既有outbox及媒体，不删除已送达修订。旧版本可忽略新增字段；不得以回滚重新生成大杂烩身份。
