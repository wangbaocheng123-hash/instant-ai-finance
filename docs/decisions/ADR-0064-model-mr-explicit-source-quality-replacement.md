# ADR-0064：模型先生单条源清晰度替换与显式防重复处理

- 日期：2026-10-12
- 状态：已采纳、已实现并正式发布；手机视觉验收待所有者确认
- 目标版本：即时 AI `0.28.2`；北京博主采集器 `1.1.1`；北京模型下载器 `0.10.5+git.exact-profile-hd`

## 背景

ADR-0055 从新作品开始默认把画面长宽约缩小一半，以控制手机流量和服务器容量。本次所有者
只要求把刚发布且已下载的模型先生视频改为高清：如果当前副本已经压缩，就重新下载同一作品
的最高画质，不压缩视频；不得批量改历史作品，也没有要求永久关闭默认轻量化。

现场以精确抖音作品 ID 核对到目标为 `7695675202135444145`，发布时间
`2026-10-12T15:10:10+08:00`。北京现有文件为 288×512、6,422,843 字节，证明已经过
ADR-0055 半尺寸处理。新加坡同一作品已保存正式原文与关键词，因此只换媒体不应再次产生
转写、提炼或原文就绪通知。

## 决定

1. 默认采集路径保持 ADR-0055 不变。新增的运维入口必须接收 15–22 位精确作品 ID；不接受
   “最新”、标题或目录扫描等模糊目标，一次只处理一条已下载视频。
2. 解析结果的作品 ID 必须与目标相同。最高画质候选下载到正式文件同目录的隐藏暂存区，使用
   ffmpeg `-c:v copy -c:a copy -movflags +faststart` 只重封装，不缩放、不重编码、不改变像素
   格式。输出必须同时有视频和音频，视频与源候选的编码、像素格式和尺寸相同；长宽不得降低，
   像素总数必须严格高于现有副本；时长差不得超过 2 秒或原时长 2% 中较大者。
3. 下载和核验期间继续保留旧文件。校验完成后先建立隐藏备份，再以同文件系统 `os.replace`
   原子切换；媒体元数据与独立 `hd_redownload_runs` 审计在同一 SQLite 事务完成。数据库失败
   立即恢复旧片。暂存目录创建等早期异常也必须写失败状态。
4. 同一作品使用旁边普通文件的跨进程非阻塞 `flock`。并发第二次请求在写审计或媒体前失败；
   锁文件保留在 Git 外，避免删除 inode 造成第三进程绕过等待者。
5. 北京签名桥在状态为 `running` 时跳过该作品，避免看见文件已切换、事务尚未完成的中间态。
   仅当 `hd_redownload_runs` 已完成，而且完成时间等于当前 `videos.downloaded_at`、结果字节数
   等于当前文件时，签名清单才增加白名单值
   `work.media_update_kind=source_quality_replacement`。该值也进入修订签名；后续普通媒体修复会因
   时间或字节数不匹配自动失去标记。字段缺失的旧清单保持字节摘要兼容，未知值拒绝。不能仅凭
   “同作品 ID + 新 SHA”猜测高清替换。
6. 新加坡只有在显式标记存在、旧新类型均为视频、媒体 SHA 改变，而且该作品已有非空正式
   原文和关键词完成元数据时，才保留原文/关键词并跳过自动处理。该决定随当前媒体 SHA 持久化，
   即时回调与重启补偿扫描均不创建任务，但仍推进水位。新作品、资料不完整作品、无标记媒体
   修复或类型纠正仍执行原处理流程。
7. 旧压缩媒体和传输内容对象不在本轮主动删除。正式文件原子替换后，北京签名桥自然产生同一
   来源作品的新修订；新加坡内容寻址保存新对象并把现有作品指向高清媒体，不新建第二条作品。

## 备选方案与取舍

- 全局关闭压缩：会改变所有后续作品的容量与流量契约，超出本次范围，未采用。
- 直接覆盖现有文件后再检查：失败时会中断播放或丢失可用副本，未采用。
- 只按新 SHA 推断高清替换：可能把错配媒体修复、损坏文件修复或图文转视频误判为无需处理，
  未采用；使用签名清单显式标记。
- 再建外部媒体/记忆服务：没有必要，也违反现有单主人资料边界，未采用。

## 验收、发布与回滚

隔离测试必须覆盖真实 ffmpeg stream copy、默认压缩保持不变、分辨率未提升、作品 ID 或时长
不一致、数据库失败恢复、跨进程并发拒绝、清单可选字段摘要兼容、无显式标记的新 SHA 不跳过、
即时回调和重启补偿均不产生付费处理或重复事件。发布顺序固定为先新加坡接受并识别标记，再发布
北京套件，最后临时停止北京签名桥、模型下载器及其 Web 单元，对精确 ID 执行同步重下，并无条件
恢复三项服务。代码中的 `running` 跳过仍作为异常时序的独立保护。

真实执行时，抖音把冷启动的直达作品页重定向到 `/jingxuan`。因此高清运维路径进一步收窄为：
先在同一持久浏览器中打开作者主页，只点击精确 ID 卡片一次；支持切换到该 ID 的新页面目标；确认
精确页面后才建立 Network 事件屏障并重新触发可见主视频。屏障前的主页预览、无新请求起点的迟到
响应、精选页、推荐页、伪域名和错误 ID 一律拒绝。普通新视频下载和默认轻量压缩路径不变。

本次目标因平台主页暂时不再显示该卡片，最终使用下载当时仍有效的浏览器缓存恢复源地址。一次性
恢复同时核对缓存详情响应中的 `aweme_id`、188600 毫秒时长、最高 H.264 码率项与媒体缓存路径，
再进入同一正式 staging、stream copy、音视频/尺寸/时长校验、原子替换和 SQLite 事务流程。结果为
288×512、6,422,843 字节升级到 720×1280、34,100,881 字节；恢复脚本和临时地址均未保留。

回滚代码不得删除已经校验的高清文件或内容对象。若重下验收失败，旧正式文件仍在；若原子切换
后的数据库提交失败，程序自动恢复旧副本。真实操作结果、签名投递与手机视觉验收写入状态账本，
不得用隔离测试冒充。
