# ADR-0059：模型先生本人评论回复的连续解读事件

- 日期：2026-10-06
- 状态：`ACCEPTED / IMPLEMENTED / NOT RELEASED`
- 候选版本：即时 AI `0.26.0`
- 决策者：产品所有者
- 关系：扩展 ADR-0058 的事件目录与最小去重索引，不改变其连续解读、只读补证、无报告回填和通知分开验收的约束。

## 背景与边界

所有者要求：除了新视频原文，还要对评论区模型先生本人的回复进行解读，结合对应视频原文及相关观点，在 ChatGPT 提醒查看。

现有北京签名评论包已经包含作者标记、正文、时间与线程关系。新加坡已有独立模型先生投影及 `get_model_mr_author_replies` 只读工具，但 `model_mr.original_ready` 只代表视频原文就绪，不能冒充评论更新事件。原新视频订阅已由真实 callback 与服务器落库确认有效，不删除、不覆盖。

本次只实施、测试新加坡应用候选；新增事件正式发布和真实订阅另待所有者确认。北京采集、评论刷新频率、资料同步、视频识别和时变罗盘均保持原样。通知时效取决于既有北京采集与同步，不保证作者发布瞬间送达，也不保证获取平台所有回复。

## 决定

1. 在同一 `/mcp` 增加 `model_mr.author_replies_updated` 事件，继续使用单主人 OAuth、签名挑战、Standard Webhooks 和原投递 worker；不增加定时采集、外部通知/记忆服务或 OpenAI API 密钥。
2. 只接受规范化来源身份 `author`、`author_comment`、`author_reply`。同名网友、普通粉丝评论和作者点赞不算本人发言。默认不预先按“是否重要”删掉本人回复；客套/表情回复可由 ChatGPT 简短说明“没有新增判断”，不编造观点。
3. 接在已验签、校验媒体和评论包的 `ModelMrTransferProjector.project` → `ModelMrClient.import_beijing_work` 路径，评论保存后触发，与原文识别独立。原文未就绪仍可通知，解读必须注明缺口，不能主动重跑 ASR。
4. 去重按作品 + `SHA-256([规范化正文, 发布时间])`，排除显示名、行号、点赞数、回复数和线程修复。引用形如 `reply-<64位哈希>`，不是平台来源评论 ID。相同作品中正文和时间都相同的记录只消费一次；正文或时间变化算新证据，但不能据此声称已识别某一平台评论的编辑关系。缺失时间时，同正文会合并；不伪造缺失时间或身份。
5. 复用 Git 外 `mcp-events.sqlite3`，新增 `author_reply_baselines` 和 `author_reply_seen`，只保存作品编号、初始化时间和已消费哈希。事件仅保存 `record_id`、`reply_refs`、`reply_count`；同一到达批次每个作品最多100个引用一批，超量拆批。无评论正文副本、粉丝信息、报告、分析、摘要或观点记忆；不是外部记忆写入服务。
6. 基线按需建立，不遍历历史库。第一次该作品到达时，在替换前读取已有保存评论并记为已消费，不通知历史；真正首次导入作品的旧基线为空，本批首次同步到的本人发言可以触发，必须在解读中区分回复发表时间与本次同步时间。无订阅期间已消费事件不在后来订阅时重放。
7. 使用导入锁内的 `before` / `saved` 两阶段交接。`before` 首次初始化旧评论基线；已有基线时，先补交上一次“保存成功、事件交接未完成”的现存正文，然后才接受下一修订覆盖。`saved` 在详情、快照和传输映射落盘后交接新增引用。事件、投递记录和已消费哈希在同一 SQLite 事务提交；失败向签名 complete 返回失败，由既有发送端重试。相同/更高修订重试不吞事件，旧修订不触发。不会为补偿再次识别视频。
8. 扩展既有 `get_model_mr_author_replies` 的可选 `reply_refs`（1–100个唯一合法引用），先精确筛选再分页；不增加第十个 MCP 工具。保留对应根提问正文，不泄漏粉丝账号/主页、来源评论 ID 或内部线程哈希；不传引用时保留原分页与每线程30条上限。精确读取时对重复引用合并，支持最多100条证据，不受默认30条截断影响。缺失引用列入 `unavailable_reply_refs`，作品不存在返回 `found=false`；不能以其他评论替代。
9. 原评论投影不是永久证据档案。事件投递前回复被删除或修改时，旧引用可能已无法读取；报告须明确证据不可用，不从哈希还原正文或编造。线程仅保证能读取到的根问题，不假装拥有未采集的中间楼层。
10. 在原长期 Work 对话额外订阅新事件，保留新视频订阅；报告先给核心判断，再说明“原问题 → 本人回复 → 对应视频/历史判断 → 延续、补充、变化或矛盾”，更新仅与本次有关的观点跟踪。历史观点注明日期与标题；既有 GPT 分析不是原文证据，重要变化回看原文。完整报告只显示在 ChatGPT，不回写任何产品，不自动交易。

## 验证与发布门禁

- 本地合成测试覆盖真实导入/只读读取路径、身份隔离、旧基线、首次到达、正文/时间去重、互动数/重排/线程变化、消失重现、重启、过期修订、事务失败恢复、交接成功但响应丢失、100条拆批、精确读取超过30条、根问题、分页/不可用引用、鉴权、最小载荷、订阅隔离及九工具兼容。
- 完整 Python 回归和编译、前端契约及生产构建、静态资源一致、依赖审计和 Git 泄漏检查通过后形成候选。未使用真实资料触发测试事件或付费调用，未执行发布。
- 正式发布后先刷新同一插件连接使新目录/参数可见，再在原长期 Work 对话新增订阅，不重新创建新视频任务。检查 callback/落库，然后等待一条自然新回复，分别验证正文、引用证据、同内容去重、ChatGPT Activity 和手机 push。Webhook 2xx 不等于报告完成或手机送达。
- 不把已经成功的新视频订阅当成新回复订阅已成功；版本、事件目录、订阅、自然报告和手机通知分别验收。

## 回滚

回退应用代码停止新回复事件的生成；新视频逻辑及其现有订阅不变。保留 Git 外事件/去重账本，不删除评论、原文或媒体，不借回滚重放历史或增加报告回填。
