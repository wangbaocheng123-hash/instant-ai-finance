# ADR-0071：榫卯社区使用可恢复的匿名浏览器身份

- 状态：`ACCEPTED / LIVE`
- 日期：2026-10-15
- 决策者：产品所有者

## 背景

社区后台按匿名访客随机标识生成固定的“木友-XXXXXX”名称。0.3.4只把该标识保存在第一方Cookie中；浏览器一旦丢失Cookie，同一位访客再次进入就会取得新名称。产品所有者要求重复访问尽量识别为同一身份，并询问是否应以首次访问IP识别。

## 备选项

1. 保存IP或以IP派生身份：移动网络会更换IP，多人也可能共享出口IP；既不可靠，也扩大隐私数据范围。
2. 使用设备指纹：可以跨部分存储清理识别浏览器，但会收集更多设备特征，不符合公开社区的最小统计边界。
3. 保留随机第一方标识，并用同源浏览器本地存储作为Cookie丢失时的恢复副本：不增加真实身份数据，同时改善同一浏览器重复访问的稳定性。

## 决定

1. 继续使用高熵随机匿名标识；服务器数据库只保存其SHA-256摘要，不保存原始标识。
2. 服务器以一年期HttpOnly、SameSite=Lax第一方Cookie为主，并在每次接受统计事件时刷新有效期。
3. 同源统计响应返回当前匿名标识，由首页脚本保存到自己的`localStorage`。后续请求在Cookie缺失时可提交该副本，服务器验证格式后恢复原标识并重建Cookie。
4. Cookie与本地副本冲突时以服务器收到的有效Cookie为准，响应会修正本地副本，避免已有访客被前端旧值改名。
5. 不保存IP、不建立设备指纹、不把匿名标识用于登录或后台授权。清除全部站点数据、无痕窗口、换浏览器、换设备或换域名仍视为新访客。

## 理由与影响

随机第一方身份比IP更稳定，也不会把共享网络中的不同访客错误合并。双存储只能提高同一浏览器、同一域名下的恢复能力，不能也不应绕过用户主动清除数据或浏览器隐私隔离。原有Cookie有效的访客继续沿用原标识和名称；已经产生的历史重复访客记录不根据IP猜测合并。

## 证据

- 社区身份相关测试及完整28项本地测试通过，覆盖首次取得随机身份、Cookie缺失后用浏览器副本恢复、后台仍只计一位访客，以及非法副本拒绝。
- `app.js`与后台脚本JavaScript语法检查通过；数据库schema测试继续确认没有IP或完整User-Agent字段。
- 本决定最初形成0.3.5候选，未单独发布，现已随聊天式布局正式上线0.3.6。公网脚本包含同源存储与恢复逻辑；北京回环和公网版本均为`15bbb4c3929ac4ed5b1d7032e6aca5b866cc5546`/0.3.6。

## 替代与撤销

本决定只扩展ADR-0068中的第一方匿名访问统计，不改变ADR-0067的独立社区服务边界或ADR-0070的单主人后台登录。若未来要跨设备保持身份，必须由所有者另行决定显式登录方案，不能回退到IP或隐蔽指纹。
