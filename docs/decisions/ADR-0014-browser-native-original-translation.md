# ADR-0014：原文交给默认浏览器翻译，产品只保留摘要备用

- 状态：`ACCEPTED`
- 日期：2026-08-28
- 决策者：用户在 iPhone 已把 Chrome 设为默认浏览器，并明确批准执行本方案
- 替代：ADR-0013 的正文抓取与正文译文方案；ADR-0009 中手机入口默认以独立 Web App 方式运行的部分

## 背景

即时 AI 已能翻译标题，但完整新闻属于来源网站，可能很长、动态渲染、受登录或付费限制。把正文抓回即时 AI 会增加流量、存储、翻译额度和版权边界，也不能稳定覆盖 Reuters、FT、WSJ 等来源。用户希望点击新闻后直接阅读由手机浏览器翻译的原站完整页面，并已经把 iPhone 默认浏览器改为 Chrome。

## 决定

1. 新闻详情的主按钮改为“浏览器翻译原文”，使用普通 HTTPS 外链和新标签页交给手机默认浏览器处理；即时 AI 不嵌入 Chrome、不接管 Google 账户，也不承诺绕过来源的登录或付费限制。
2. Web App 清单的 `display` 从 `standalone` 改为 `browser`。iPhone 旧主屏幕图标需要删除后，从 Chrome 重新“添加到主屏幕”；若系统显示“作为网页 App 打开 / Open as Web App”，应关闭该选项，使入口保留浏览器界面和翻译能力。
3. 用户在 Chrome 中对英文新闻启用翻译，并可选择“始终翻译英语”。翻译质量、可用语言、页面兼容性和 Google 服务可用性由 Chrome 与当前网络环境负责，产品不伪装成自己完成了全文翻译。
4. 原“中文阅读”降级并更名为“中文摘要（备用）”。服务端只翻译采集源已经提供并存入当前消息的 Feed 摘要，绝不为该功能下载新闻正文页面。
5. `reader_translations` 继续作为短期摘要译文缓存并随消息到期级联清理。0.9.1 指纹加入 `summary-only-v1` 策略标记，旧 `article_excerpt` 缓存不会命中新方案；无需新增数据库迁移。
6. Service Worker 缓存版本升至 0.9.1，API 仍然 `no-store` 且不进入离线缓存；五分钟采集和前台恢复刷新机制不变。

## 理由

浏览器原生翻译直接作用于发布方当前页面，能覆盖正文、图表说明和后续更新，不需要即时 AI 建立全文库。摘要备用只处理已经采集的少量文字，继续满足快速判断事件重要性的需要，同时显著降低流量、存储、翻译额度和合规风险。

## 限制

- Web 页面不能强制指定 Chrome，也不能自动替用户开启“始终翻译”；它只能交给系统默认浏览器。用户当前已将 Chrome 设为默认浏览器。
- 付费墙、登录、地区限制、反自动化或来源自身故障仍由原站决定，浏览器翻译不会解除这些限制。
- 已安装的旧 standalone 主屏幕入口不会仅靠服务器更新自动改变运行模式，必须删除旧图标并重新添加一次。

## 验收证据

- 产品提交 `7352522`：原文按钮、浏览器提示、browser manifest、0.9.1 缓存版本和摘要-only 服务端策略。
- 单元测试用 `urllib.request.urlopen` 禁用断言证明摘要备用不会触发正文网络请求；18 项测试全部通过。
- TypeScript/Vite 生产构建通过，`npm audit --audit-level=high` 为 0；本机 `/api/health` 返回 0.9.1，完整运行验收通过。
