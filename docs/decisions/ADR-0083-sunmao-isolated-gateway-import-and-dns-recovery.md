# ADR-0083：社区独立网关配置与备案后入口恢复

- 状态：LIVE；中文原DNS记录已启用，普通公网及右侧浏览器验收通过，英文服务器配置修复保留。
- 日期：2026-11-09。
- 关系：补充ADR-0069，不改变社区独立应用或Git外数据位置。

## 事实

所有者确认中文域名备案通过，并授权本次使用右侧阿里云页面。北京社区仍为0.3.10/0503e77，隧道健康；新加坡共享Caddyfile的11月7日更新移除了精确英文站点，造成TLS握手失败。两个根域的权威DNS查询又均无A地址，需要分别处理配置和DNS，不能把任一项成功等同普通公网已恢复。

## 决定及实施

英文站点独立保存在`/etc/caddy/sunmao-community.caddy`，由不归时变罗盘总配置管理的既有`Caddyfile.instant-ai`追加精确import加载。保持共享配置原字节、MCP块、即时AI块；不增加通配符、不改变上游或复制社区数据。脚本提供事前校验、备份、失败回滚和幂等。

Caddy 2.11.4关闭admin API，常规reload失败后已回滚文件；随后按官方信号方式平滑加载，进程标识未变。Windows和北京外部定向请求均返回同一完整SHA；中文定向北京HTTPS也正常。

所有者进一步澄清英文仍在申请备案，本轮只将已备案中文作为正式入口。17:14通过右侧阿里云页面确认唯一中文根A原记录地址北京47.93.214.76正确但为暂停，已直接启用，页面显示操作成功和17:14:46更新时间。未改英文根DNS、MCP或新增记录。中文备案通过由所有者确认，未将其冒充为控制台查验结果；右侧页面实际由`cua_repl`接通，不导出任何会话凭据。

操作端发布验收改为中文`https://xn--4pv19va7008a.com/health/version`。在推进任何生产引用前检查中文HTTPS的服务身份，不就绪立即停止，避免DNS未恢复时先推生产再等待15分钟。该操作端变更无需应用重启。

## 完成条件

中文权威DNS返回北京地址，中文普通公网HTTPS、精确版本、同一资料数据及后台保护全部通过；英文DNS、MCP DNS/站点保持，各业务服务不重启。英文备案或公网恢复不再作为本次任务完成条件。详细步骤见社区`deploy/singapore/README.md`。

## 完成证据

新加坡普通DNS返回北京地址；普通中文HTTPS未使用服务器定向或跳过证书验证，返回0.3.10/`0503e77649bd9e34ef7240ff606de012fc824880`、5资料/4文章/24张完整原图/3视频入口，首页/后台200、未登录统计401。右侧浏览器已通过普通中文网址打开尺寸页并显示5条资料。北京社区、采集器、下载器及Caddy InvocationID未变，未推进生产分支或写业务数据。Windows曾有旧DNS负缓存，无法由一次外部成功推断所有运营商同时刷新。
