# ADR-0091：大杂烩固定链接作品库与北京入口故障边界

- 日期：2026-11-21
- 状态：`IMPLEMENTED / MAIN_CANDIDATE / DNS_AND_PRODUCTION_PENDING`
- 候选版本：北京博主采集器 `1.3.0`
- 来源：所有者要求把任意博主的一条抖音链接放入统一“大杂烩”，下载后沿现有北京→新加坡通道进入即时 AI；同时排查手机采集端显示“采集端读取失败：Load failed”。

## 现场结论

北京应用本身没有宕机。只读检查确认 `blogger-collector.service`、Caddy 均为 active，Git 定时发布保持 disabled/inactive；回环 `/health`、`/health/version` 和 `/api/collector/dashboard` 正常，传输配置 ready，生产仍为 `1.2.0`、提交 `10fdb3a`，近期服务日志没有对应崩溃。

截图故障发生在公网入口：`collector.amuyeye.com` 与候选 `collector.grandpaamu.com` 均没有可用 A 记录，多个公共递归解析器返回 NXDOMAIN/空答案。手机已安装 PWA 仍可从 Service Worker 缓存显示旧页面壳，但页面随后无法请求 API，Safari 因而只显示通用 `Load failed`。使用旧域名 SNI 直接指向北京回环网关时，版本接口和登录跳转正常，证明旧北京 Caddy 站点仍可服务；新域名的网关、证书和公网验收尚未完成。

最小恢复动作是先在阿里云 DNS 重新启用旧记录 `collector.amuyeye.com A 47.93.214.76`，再用普通公网 DNS/HTTPS 验证。不要把 `collector.grandpaamu.com` 直接指向北京 IP：ADR-0086 所需的备案/网关选择、真实 SSH 转发、Caddy/TLS 和登录验收尚未完成。本次运行环境没有可用的 AliDNS RAM 凭据或网页控制工具，因此没有伪造 DNS 修复结果，也没有修改 Caddy、证书或生产应用。

## 大杂烩行为

1. 采集端自动提供一个内置 `大杂烩` 标签，类型为 `link_only`。它没有博主主页、不参加主页扫描或自动轮替，名称和主页字段不可改，只保留评论开关与数量设置。
2. 点击“大杂烩”的主按钮后必须粘贴一条抖音视频链接或完整分享文案。复用既有的单条视频解析、作品 ID 校验、下载、评论采集和内容完成回调；链接识别本身不启动 Chromium，确认后也只处理该作品。
3. 大杂烩使用独立来源 `douyin-link-bucket`（图文为 `douyin-link-bucket-image`）和独立运行目录。作品查重同时限定归档作者和抖音作品 ID，避免同一作品先在真实博主库、后在大杂烩出现时改名、迁移或覆盖原记录。
4. 新建大杂烩使用固定 UUID `6fe1c729-3b3d-5a0f-b628-5e898f9d2a41` 和固定平台身份 `instant-ai-miscellaneous`。若现有配置已经有名为“大杂烩”的人工博主，则升级为链接作品库并保留它原有的 UUID，避免已传到新加坡的作品被拆成第二个资料库。
5. 北京到新加坡的 HMAC、持久 outbox、媒体摘要、幂等和回执协议不变。传输清单中的 creator 身份固定为大杂烩，因此即时 AI 按原有博主 UUID 分组，后续作品统一显示在同一个“大杂烩”下；收费 ASR/AI 是否自动执行仍服从即时 AI 既有审批和处理设置，本决定不放宽计费边界。
6. 网络请求失败时，前端把 Safari 的模糊 `Load failed` 改为“无法连接北京采集服务，页面可能来自离线缓存，请检查域名或 DNS”，并升级 PWA 壳缓存版本，避免故障被误判为采集任务失败。

## 验收与发布

- 覆盖固定身份、现有大杂烩迁移、不可绑定主页、必须提供单链接、无主页下载、同作品跨库不串记录、传输清单固定归档、HTTP 拒绝无链接任务和手机页面契约。
- 完整北京采集器 237 项 Python 回归通过；JavaScript 语法、Python 编译及 Git 差异检查通过。
- 本轮只形成 `main` 候选。没有所有者约定的正式发布口令，不推进 `beijing-production`，不启动一次性北京发布服务。生产仍为 `1.2.0`；DNS 恢复、普通公网入口验收、正式发布和一条真实公开视频的北京→新加坡回执必须分别记录。

## 回滚

回滚应用代码会撤掉内置链接作品库入口，不删除已下载媒体、SQLite 记录或 outbox。已经存在的“大杂烩”UUID必须保留，不能通过重建配置让新加坡出现第二个同名资料库。DNS 恢复与应用版本相互独立；回滚代码不应再次停用域名记录。
