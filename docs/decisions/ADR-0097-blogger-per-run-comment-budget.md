# ADR-0097：单次评论采集计时，到时保留结果并交付

- 日期：2026-11-28
- 状态：IMPLEMENTED / TESTED / RELEASE_PENDING
- 目标版本：北京博主采集器1.3.3
- 所有者澄清：需要的是点击指定视频后，对该作品的评论采集持续指定分钟并到时结束；0已再次明确为“不抓评论，只下载视频”。模型先生必须继续抓取视频。本轮延续先前“完善结束以后直接发布”的授权。

## 行为及旧设置

本决定替代ADR-0096中用作品发布后的跟踪窗口满足本需求的界面和解释。数量0的单链接行为保留。新字段`creator_comment_collect_minutes`/API `comment_collect_minutes`单独保存本次每条作品的抓评预算，0～60分钟；0跳过评论浏览器，仍下载视频、登记并沿原outbox发送。5表示进入评论阶段后最多300秒；视频下载/转码、排队等待不计入这300秒，结束后的本地合并和传输仍需时间。

旧`creator_comment_tracking_hours/minutes`是作品年龄窗口，整小时值不映射为单次运行预算，避免既有24小时被误当成连续采集一天。旧字段和旧客户端兼容仍保留，新运行预算缺省为原程序已有的180秒（3分钟）。唯一迁移例外是1.3.2已在分钟输入框保存的1～59分钟值：视作本需求下的明确分钟选择保留；现场目标博主原5分钟会成为新运行预算5分钟，普通60/1440分钟仍用3分钟缺省。已有新预算（含0）始终优先。评论总数上限、来源公开页可见范围保持；全部公开页完成或达到数量上限时可提前结束，不承诺时间内获得所有评论。

## 到时保存

评论采集器进入时用单调时钟建立截止时间，包含自己的浏览器准备和页面导航；浏览器启动等待、回环请求、CDP命令等待和事件读取均按剩余预算收紧。截止后不继续发起滚动/展开/响应读取，返回此前已经取得的评论；正常释放自己的评论浏览器后，由原存储流程合并评论和回复，再调用原持久发送回调。

摘要增加`stop_reason`（time_limit/source_exhausted/comment_limit）、预算与耗时。到时是正常有界结束，不写为下载错误；不完整快照保持`complete=false`。管理中心区分“最多几分钟抓评”和“到时已保存”。0同时由API的videos_only和执行器评论判断保护，强制补抓不会绕过0。

不新增全局停止信号、cron或timer；计时只属于本次博主评论调用。`services/beijing-model-downloader/`没有变更，其视频扫描、下载和评论调度保持原样；发布时模型子树未变化必须跳过构建/重启，前后核对模型worker/web InvocationID及active。原共享登录、独立目录、签名传输与计费边界保持。
