# ADR-0056：模型先生作品与评论统一使用北京时间契约

- 日期：2026-09-23
- 状态：`ACCEPTED / IMPLEMENTED / RELEASED`
- 目标版本：即时 AI `0.23.2`；北京博主采集器 `1.0.9`；北京模型下载器 `0.10.3+git.beijing-time`
- 决策者：产品所有者明确要求按中国北京时间核对并校正模型先生时间

## 背景与现场证据

所有者看到模型先生最新作品显示为 `9 月 24 日 01:59`，但该时间与作品实际发布时间不符。
北京生产库只读核对得到作品 `7688668173143610297` 的 `published_at` 为
`2026-09-23T17:59:19`；同一作品 ID 高 32 位解出的 Unix 秒级时间为
`2026-09-23T09:59:19+00:00`，换算北京时间正好是
`2026-09-23T17:59:19+08:00`。因此真实发布时间是 9 月 23 日 17:59，而不是次日 01:59。

根因是北京模型下载器历史上用服务器本地时区生成时间，却把值以不带时区的 ISO 字符串保存；
只读传输桥遇到无时区字符串时错误附加 UTC。手机浏览器再从 UTC 转为北京时间，重复增加八小时。
这不是抖音作品 ID、手机时钟或服务器系统时区错误；北京服务器本身已是 `Asia/Shanghai`。

## 决定

1. 北京模型下载器从作品 ID 和评论 Unix 时间戳生成时间时，必须显式使用
   `Asia/Shanghai`，入库值带 `+08:00`，不再依赖进程或系统默认时区。
2. 北京只读传输桥兼容历史资料：无时区的模型下载器时间一律解释为北京时间；已经带
   `Z` 或其他偏移的时间保留其原始时区语义，不能再统一强贴 UTC。
3. 作品修订指纹使用规范化后的发布时间。旧的无时区作品因此自然产生一次新修订，把正确的
   `+08:00` 时间送到新加坡；相同视频仍按 ADR-0055 的 SHA-256 内容对象复用，不重复上传或
   保存完整 MP4，只传需要更新的清单与评论包。
4. 即时 AI 的模型先生页面无论手机当前设置为何，都固定用 `Asia/Shanghai` 格式化作品和评论
   时间。MCP 与主人 API 继续返回带偏移的标准 ISO 时间，不用前端硬减八小时。
5. 不直接批量改写北京 SQLite 或新加坡主人资料文件。新作品从源头正确保存；历史作品通过
   可审计的签名修订逐条校正，保留原修订账本、标题、视频、原文、关键词、评论和解读。

## 验收与发布门禁

- 回归必须固定本次真实秒级样例：`09:59:19Z` 等于 `17:59:19+08:00`。
- 模型下载器作品和评论两条路径都必须输出带 `+08:00` 的时间。
- 传输桥必须把历史无时区值规范化为 `+08:00`，同时保持显式 UTC 输入不变；规范化时间必须
  进入修订指纹，保证旧错误投影会被重新发送。
- 页面源码与生产构建必须固定 `timeZone: 'Asia/Shanghai'`，Service Worker 随 0.23.2 换缓存。
- 候选回归结果：即时 AI 207 项、北京采集/传输 223 项、模型下载器 27 项、北京发布控制
  32 项、前端源码契约 10 项与共享评论逻辑 6 项全部通过；Vite 0.23.2 构建、静态产物一致
  和 npm 高危审计通过（0 漏洞）。
- 正式发布须分别走新加坡固定发布器与北京 `beijing-production` 统一发布器。北京投递完成后，
  以最新作品核验 API/MCP/手机均显示 9 月 23 日 17:59；不得把候选代码误报为已上线。

## 正式发布结果

- 2026-09-24 所有者明确要求发布。新加坡固定发布器将生产上线到
  `8a68388381e72056184738f82452498a00bf541e`，服务器 207 项测试通过；公网健康、Service
  Worker 和 MCP initialize 均为 0.23.2，正式页面资源包含 `Asia/Shanghai`。
- 北京 `beijing-production` 推进到同一提交；采集器 1.0.9、模型下载器
  `0.10.3+git.beijing-time` 与统一发布器全部成功，三个业务服务 active。
- 发布后共有 49 个作品形成校时修订，49 条均携带 `+08:00` 并以 HTTP 200 送达。真实样例
  `7688668173143610297` 的最新 revision 53 为 `2026-09-23T17:59:19+08:00`，旧 revision
  52 的 `+00:00` 错误值已被新修订覆盖；媒体摘要不变，没有重复上传 MP4。
- 北京 GitHub 直连短暂超时期间没有切换业务。用于恢复 Git 获取的一次性回环通道已关闭，
  systemd manager 和 blogger/model/model-web 进程均无代理变量残留，发布 timer 保持关闭。
- 服务器、传输与共享投影已经验收；手机主人会话的最后视觉确认仍由所有者完成，不能用未登录
  检查冒充真机结果。

## 回滚

代码可回滚，但已写入或投影的带偏移 ISO 时间仍是合法标准时间，无需反向改回无时区字符串。
如传输过程中断，既有 outbox 会按原幂等规则重试；媒体摘要不变，不会因时间修订产生第二份视频。
