# ADR-0013：按需中文阅读与短期译文缓存

- 状态：`ACCEPTED`
- 日期：2026-08-28
- 决策者：用户要求执行新闻原文汉化方案并查看实际效果

## 背景

标题汉化可以帮助用户快速浏览，但点击英文新闻后仍会进入英文原文。即时 AI 的定位是短周期全球财经热点雷达，不是长期全文档案，也不得绕过 Reuters、Bloomberg、FT、WSJ 等来源的付费墙或访问限制。因此需要在阅读便利、公开内容边界、翻译额度和短期数据生命周期之间取得明确平衡。

## 决定

1. 新闻详情增加“中文阅读”按钮，只在用户点击时启动正文提取和翻译，不在每轮采集时批量翻译所有文章。
2. 服务端只读取公开可访问页面，并复用缩略图模块已经验证的 DNS、私网地址、重定向、响应大小和超时防护；不携带 Cookie，不登录，不绕过付费墙。
3. 优先提取 `article`、`main` 或正文段落，去除导航、脚注和重复段落；每次最多处理 3,600 个源字符、650 KiB HTML。正文不可读或受限时，自动回退到 Feed 已保存的公开摘要。
4. 翻译继续复用 ADR-0006 的提供器：默认 MyMemory 匿名公共接口，可选本机 LibreTranslate。MyMemory 与标题翻译共享每日 4,500 字符保守额度；额度不足时显示明确提示并保留“打开原文”。
5. SQLite schema 升至 6，新增 `reader_translations`。缓存以消息内容指纹和目标语言为键；消息到期删除时通过外键级联删除正文译文、英文摘录和相关元数据，不建立长期全文库。
6. 阅读页显示中文译文、来源类型和机器翻译提示；英文摘录放在可展开区域，便于核对。机器译文仅为阅读辅助，不生成投资建议。
7. 云端无账户公开入口只返回上述有界摘录和译文，不提供整站抓取、长期全文下载或付费内容解锁接口。

## 理由

按需处理把有限翻译额度集中给用户真正想读的新闻，也减少网络流量和存储。Feed 摘要回退让访问受限的来源仍有可读结果，同时不会伪装成已经取得完整正文。译文与新闻共用淘汰生命周期，符合 ADR-0010 的“无长期档案”定位。

## 影响

- 一篇较长文章可能因匿名额度或 3,600 字符上限只翻译前部，并在界面标注“节选”或“部分翻译”。
- 发布方反爬、脚本渲染、登录或付费限制会触发摘要回退；没有公开摘要时仍只能打开原文。
- 默认翻译需要联网，公开正文节选或摘要会发送到 MyMemory；以后可在用户另行部署后切换到本机 LibreTranslate。
- `reader_translations` 是短期运行数据，只进入 H 盘或云端独立数据目录，不进入 Git。

## 验收证据

- `product/instant_ai/reader_translation.py`：安全提取、正文/摘要回退、分段翻译和指纹缓存。
- `POST /api/items/{id}/reader-translation`：按需中文阅读接口。
- 18 项 Python 单元测试、Vite 生产构建和 `npm audit --audit-level=high` 通过。
- 390×844 手机视口实际验证“中文阅读”、额度提示、英文原文入口和响应式详情页，浏览器控制台错误为 0。
- 阿里云 0.9.0 真实英文样本 1034 首次生成完整中文摘要，第二次请求命中短期缓存；正式域名和应急域名健康接口均为 0.9.0。

## 关系

本 ADR 扩展 ADR-0006 的标题汉化，并继续遵守 ADR-0010 的短期淘汰和 ADR-0011 的无账户公开入口边界。
