# ADR-0077：新加坡云端智能体按统一契约接收榫卯资料

- 状态：`ACCEPTED / OPERATING RULES READY / INGEST API NOT YET LIVE`
- 日期：2026-10-16
- 决策者：产品所有者

## 背景

所有者将主要通过手机向新加坡云端 Codex 提供尺寸、图纸、3D 模型、视频、文章和文字说明，希望后来加入的智能体能够一眼看懂资料应该归入什么类目、写到哪里、如何核实，以及何时真正对社区访客可见。ADR-0076只决定了北京云端知识库的物理位置，仍需规定接收与分类流程。

## 决定

1. `services/sunmao-ai-community/AGENTS.md` 是社区任务入口；新加坡云端 Codex 必须读 `docs/KNOWLEDGE_INTAKE_RUNBOOK.md`、`config/knowledge_taxonomy.v1.json` 和 `docs/CLOUD_KNOWLEDGE_LIBRARY.md`，并核对当时实际运行能力。
2. 分类采用“一个主题条目 + 多种资料形式”的结构。`primary_topic` 与 `resource_kinds` 使用稳定代码；“尺寸型”和“榫卯108道”是展示视图，不是互斥文件夹。分类变化不移动原始文件。
3. 接收时保留来源、去重与版本关系。所有者直接提供的信息可按其原意录入；从资料中提取的事实保留定位；AI 推断的工程尺寸不自动发布。分类或授权不明时只暂停受影响字段，并继续可核实的部分。
4. 云端正式知识只落北京社区自己的数据库与资源目录。新加坡 Codex 是操作端，不建立第二份社区数据库；Obsidian、本地电脑和公开 Git 不是线上资料源。第三方视频与文章默认保留原链接。
5. 现有代码只支持静态外链索引，尚无通用云端知识后台。智能体不得把写入 Git 的候选清单称为“已进知识库”或“公网可见”。后台建成后走受保护录入/审核 API；普通内容发布和代码发布分别报告，代码上线仍遵守社区正式分支规则。

## 验收

- 新智能体仅凭仓库指令能正确区分主题类目、资源形式、页面视图和数据位置。
- 用“榫卯结构 + 尺寸 + 3D + 视频”的示例，不产生四个相互割裂的知识主题。
- 用不可访问的微信文章、无单位模型和第三方视频示例，不会编造尺寸、声称已读全文或复制媒体。
- 当前能力与未来后台明确分开；状态报告能区分整理、开发分支、北京知识库和公网四个阶段。
