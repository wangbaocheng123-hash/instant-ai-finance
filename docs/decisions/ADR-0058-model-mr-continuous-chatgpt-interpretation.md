# ADR-0058：模型先生原文就绪后在 ChatGPT 对话内连续解读

- 日期：2026-10-05
- 状态：`ACCEPTED / IMPLEMENTED / NOT_RELEASED`
- 目标版本：即时 AI `0.25.0`
- 决策者：产品所有者

## 背景与核实结果

所有者要求把“模型先生新视频自动解读”从孤立的单条摘要改为连续观点分析，并明确禁止
把报告、摘要或观点记忆回填即时 AI、模型先生资料库或时变罗盘。

核对现有代码后确认：0.24.0 只有送达后的“原文识别 → 关键词提炼”和九个只读 MCP
工具，没有原文就绪事件，也没有 ChatGPT 自动解读任务。现有 MCP 能按主题搜索作品并读取
精确原文，足以按需补证；没有必要建立第二个记忆服务或报告写接口。

同时核对 OpenAI 当前官方契约：MCP Events 使用 `2026-07-28` 协议，让 ChatGPT 在订阅
该事件的 Work 对话中收到更新并按该对话里的用户指令处理。事件订阅不是“新开一个无上下文
对话”；但也不能把当前不可见、被压缩或从未读取的内容假设成永久记忆。因此连续性采用
“当前订阅对话实际可见内容优先，缺失证据再用既有只读 MCP 按主题检索原文”的双层方案。

依据：

- [OpenAI MCP Events](https://developers.openai.com/plugins/build/mcp-events)
- [ChatGPT Scheduled tasks](https://learn.chatgpt.com/docs/automations)
- [ChatGPT Notifications](https://learn.chatgpt.com/docs/notifications)

## 决定

1. **使用原统一 MCP 的标准事件，不新建外部任务服务。** `/mcp` 增加 MCP 2.0
   `server/discover`、`events/list`、`events/subscribe` 和 `events/unsubscribe`，唯一事件名为
   `model_mr.original_ready`。旧协议和九个只读工具继续兼容。
2. **事件发生点固定为原文落盘之后、关键词之前。** 新视频复用已有原文或完成豆包 ASR，
   `save_auto_video_text` 成功后立即建立事件；关键词配置缺失或后续失败不妨碍原文解读。
   事件交接失败只单独补偿，不回退原文、不重复 ASR、不重复关键词付费调用。
3. **双层去重。** 处理队列继续按作品 ID 与媒体摘要去重；事件再按作品 ID 与规范化原文
   SHA-256 去重。同一内容的回调重放、服务重启和本地交接重试复用同一事件，不创建第二次解读。
   升级时把旧处理任务标为“事件前已消费”，不把历史库或旧任务变成首次发布事件洪峰。
4. **事件只含最小索引。** 载荷仅有 `record_id`、标题、发布日期、原文状态和原文 SHA-256；
   不携带完整原文、评论、已有解读、观点、报告提示或买卖指令。ChatGPT 收到后使用
   `get_model_mr_work_text` 读取本条，用 `search_model_mr_works` 和精确读取工具按主题、时间与
   相关性补足必要历史证据，不遍历全部作品。
5. **连续性由订阅对话维护，不冒充永久记忆。** 任务先使用该对话实际可见的既有解读和
   精简“观点跟踪”；看不到的内容必须说明没有读取，随后按需检索原文。既有 GPT 解读只能
   作为分析线索，不能代替原文。判断重要矛盾、转向或条件兑现时，必须回看相应历史原文，
   并标明日期或标题。
6. **观点跟踪只出现在 ChatGPT 回复。** 每次只更新与本条有关的主题、作者原判断、提出日期、
   成立条件、后续变化和待验证问题，不完整复述所有历史。即时 AI 不增加报告、摘要、解读或
   观点记忆回填接口；模型先生资料库和时变罗盘均不接收这些输出。
7. **完整报告直接回到订阅对话。** 回复必须先给核心判断，再区分作者观点、历史事实和 GPT
   分析，说明延续/加强/减弱/改变/矛盾、事实变化与表达变化、已支持/受挑战/待验证条件、
   当前核心逻辑和下一关注点；不得只给“已完成”或报告编号，不用固定字数删掉关键联系，
   也不生成自动交易或买卖指令。
8. **订阅与投递是基础设施状态，不是观点记忆。** Git 外 `mcp-events.sqlite3` 只保存主人订阅、
   签名密钥、最小事件索引、内容哈希和投递状态；文件权限为 `0600`。Webhook 必须 HTTPS，
   在连接时解析并拒绝私网/本机/非公网地址，不跟随重定向，先做签名挑战；投递使用 Standard
   Webhooks，2xx 确认，瞬时失败有界指数重试，410/413 不重试，重试保留事件 ID。
9. **通知分开验收。** ChatGPT 对话中的完整回复是交付物，ChatGPT 通知只负责提醒主人查看。
   正式发布后分别验证 Web/桌面对话结果、Activity 未读状态和手机 push；锁屏是否展示完整正文
   不作为成功条件，也不把服务端 webhook 2xx 冒充手机通知已经送达。

## 数据流

```text
北京新视频签名送达
  → 新加坡唯一处理任务（已有媒体/原文优先）
  → 原文保存成功
  → 持久化 model_mr.original_ready（内容哈希去重）
  → ChatGPT 订阅对话收到事件
  → 精确读取本条原文
  → 使用对话内可见观点跟踪
  → 只按相关主题补读必要历史原文
  → 完整连续解读与本次观点跟踪直接显示在 ChatGPT
```

没有从 ChatGPT 指向即时 AI、模型先生资料库或时变罗盘的报告回写箭头。

## 验收与发布门禁

- 单元测试覆盖 MCP 2.0 发现、鉴权、事件目录、订阅幂等、签名挑战、私网 SSRF 拒绝、
  Standard Webhooks 签名、密钥轮换、跨重启重试、同内容去重、退订和最小载荷。
- 处理器测试证明原文事件先于关键词阶段；事件交接失败后可补偿，ASR 和关键词各自仍只调用
  一次；旧任务迁移不会触发历史事件。
- 全量 Python 回归、Python 编译、前端生产构建、静态资源一致、依赖审计和项目泄漏检查通过，
  才能形成候选。
- 本轮不正式发布。收到所有者新的“正式发布”确认后，才运行既有受限发布器；随后在
  ChatGPT Work + Cloud 中刷新连接、在目标长期对话建立订阅，并等待一条自然新视频完成
  对话全文、去重和手机 push 的真实验收。

## 回滚

回滚应用代码会停止新订阅和新事件，但不删除作品、原文、关键词或媒体。Git 外订阅/投递库
可保留以供审计；不得用回滚重放历史视频、重新识别原文或把未送达事件改写成报告回填。
