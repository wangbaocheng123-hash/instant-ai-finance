# ADR-0066：榫卯社区底部导航与公开文字交流

- 日期：2026-10-13
- 状态：公开文字与内容边界继续有效；运行拓扑已由ADR-0067替代，导航位置与交流页布局已由ADR-0072替代
- 目标版本：榫卯 AI 社区 `0.2.0`
- 前置决定：ADR-0065

## 背景

首版`阿木爷爷.com`只展示“榫卯108道”34集标题、封面与抖音跳转。所有者现要求调整页面结构：底部增加一行导航，左侧放后续工艺品尺寸连接，右侧放“榫卯108道”，同时增加类似论坛或聊天窗口的交流区，并把公开交流内容作为社区主屏。

这项要求明确替代ADR-0065中“首版不含写入能力”的阶段性限制，但没有要求建立账号、私信、图片上传或完整论坛管理系统。实现必须继续与北京采集器、模型下载器和主人管理入口隔离。

## 决定

1. 公共页面固定使用三个底部入口，顺序为“尺寸型 / 交流区 / 榫卯108道”。默认打开交流区；切换只改变当前社区视图，不新增路由服务或另建仓库。
2. “尺寸型”先提供器物尺寸、结构尺寸和图纸连接三个清晰占位，不虚构所有者尚未提供的尺寸资料或外链。后续收到资料后再增加可审计的数据和页面。
3. “榫卯108道”继续复用ADR-0065的34条Git元数据、来源域白名单和精确抖音跳转；不托管视频，不把封面或视频二进制放入Git。
4. 交流区允许游客填写称呼并发表纯文字。称呼为1—20字，正文为1—500字；不建立用户表、密码、头像、私信、附件、图片、富文本、点赞或通知能力。浏览器只以`textContent`渲染服务端内容。2026-10-16起，称呼输入与长度限制由ADR-0075替代，访客只需填写正文。
5. 消息保存到独立Git外SQLite`/var/lib/sunmao-community/community.sqlite3`，不进入采集器数据目录或业务数据库。只保存随机消息ID、称呼、正文、创建时间和内部可见标志；默认保留90天、最多5000条。
6. 公开接口限定为`GET/POST /api/messages`。POST必须由同源浏览器发起，JSON字段必须精确为称呼和正文；来源地址只在当前进程内用于至少15秒一条、每小时10条的限流，不写入数据库或日志。2026-10-16起，POST字段与兼容策略由ADR-0075替代。
7. 社区由独立、只监听`127.0.0.1:18808`的进程提供，Caddy直接代理该服务。不得暴露`/api/collector/*`、主人管理面、下载器端口或其他数据库。
8. 版本候选为社区`0.2.0`。开发完成不等于正式上线；仍须取得社区自己的发布短语，才能推进`main`到`sunmao-production`并触发独立发布器。

## 备选方案与取舍

- 完整账号论坛：会立即引入身份、密码、找回、审核和隐私责任，超出本次“谁进来都可以发表意见”的最小需求，暂不采用。
- 只做本机前端假聊天：无法让不同访客看到同一内容，不满足公开交流，未采用。
- 把消息写入采集器原数据库：会混淆公开访客内容和北京采集业务资料，未采用；使用独立SQLite。
- WebSocket实时聊天：需要额外连接治理与扩容设计；当前15秒刷新已满足轻量社区起步，暂不采用。
- 保存来源地址用于长期封禁：增加不必要的个人数据持有；当前只做内存限流，不持久化。

## 验收与回滚

发布前必须通过34集连续和来源白名单检查、底部导航顺序/默认主屏契约、纯文本安全渲染、字段长度、同源拒绝、限流和SQLite读写测试；在本地完整服务实际发表并刷新消息，切换三个入口，确认页面无横向结构异常。

正式上线后须验证公网GET/POST、第二次快速POST被限流、服务重启后消息仍在、三个入口和34条视频正常，并确认`/api/collector/*`没有被社区域名暴露。若出现滥用或存储异常，优先以新Git提交关闭POST、保留只读交流和原34集页面；应用回滚使用安全快进提交，不删除现有消息库。
