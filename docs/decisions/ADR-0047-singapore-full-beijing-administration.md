# ADR-0047：新加坡云端 Codex 全面管理北京采集套件

- 状态：`ACCEPTED / IMPLEMENTED`
- 日期：2026-09-10
- 决策者：产品所有者

## 背景

ADR-0046 的固定三命令通道已经能够发布博主采集器，但无法维护北京原模型下载器，因而
不能实现所有者“手机只连接新加坡 Codex，即可完成北京全部日常维护”的最终目标。
所有者明确要求取消应用层命令白名单，把原模型下载器与博主采集器一起纳入同一 Git
工程和发布入口，同时保留两套业务数据与进程的故障隔离。

## 决定

1. 新加坡保留原 Git 外 Ed25519 身份，北京新增锁定密码的 `singaporecodex` 登录账号，
   授予免交互完整 sudo。北京 22 端口仍只接受新加坡固定公网来源；不使用密码、代理、
   AccessKey 或把私钥放入 Git。
2. 新加坡提供 `~/bin/beijing-admin`，可打开普通 SSH shell或执行任意管理员命令。旧
   `beijingcodex` 三命令入口保留为应急兼容，不再代表云端能力上限。
3. 北京现场真实模型下载器代码受控导入 `services/beijing-model-downloader/`。导入不含
   `.env`、Cookie、密钥、SQLite、视频、评论原始 JSON、浏览器资料、日志、缓存或备份。
4. 北京采集套件继续使用一个公共仓库、`beijing-production` 和一个
   `/usr/local/sbin/beijing-suite-publish` 入口。入口分别发布博主采集器和模型下载器；
   两项服务、数据库、媒体目录及失败回滚仍相互独立。
5. 模型下载器实现 ADR-0044：按抖音发布时间未满 24 小时每 15 分钟抓评，达到 24 小时
   后每 60 分钟；按上次成功时间推进，失败不推进，同一进程串行使用 Chromium。
6. 日常流程为：新加坡 Codex 修改统一仓库、测试、推送 `main`、经所有者发布指令推进
   `beijing-production`，然后在北京执行统一发布器并核验两个服务与精确提交。电脑端不再
   是日常维护依赖。

## 边界

“完整管理”表示新加坡 Codex 在北京操作系统内拥有完整管理员能力，不表示公开服务器
登录。认证、主机指纹和 Git 外凭据隔离属于防止第三方接管的基础保护，不构成功能限制。
北京与新加坡即时 AI 仍是两个系统，继续通过既有签名资料通道通信。

## 替代关系

本 ADR 替代 ADR-0046 对新加坡日常命令范围的限制，并完成 ADR-0045 的原模型下载器
源码接入。ADR-0046 的历史受限账号可继续作为回退入口；其“原模型下载器未纳管”状态
不再适用。
