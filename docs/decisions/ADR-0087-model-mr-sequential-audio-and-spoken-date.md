# ADR-0087：模型先生按作品序号连播与中文日期提示

- 日期：2026-11-13
- 状态：`IMPLEMENTED / RELEASED / IPHONE_ACCEPTANCE_PENDING`
- 正式版本：即时 AI `0.31.0`
- 来源：所有者要求当前音频结束后自动播下一条，并在音频中报年、月、日和作品序号。
- 延续：ADR-0084 的单主人私有音频、循环、有限定时与既有全库编号；复用核验见 `research/MODEL_MR_AUDIO_SEQUENCE_REUSE.md`。

## 行为

1. 在音频播放器增加“播完自动下一条（按序号递增）”。默认仍单曲循环；勾选后从所选作品向较新的作品播放，到本次开始时资料库中的最新一条结束。不是按列表当前显示顺序倒播，也不把当前页下标或内部ID当序号。图文、缺本地视频、无可用音轨的作品跳过，所以报读序号可能不连续。
2. 每条原声前放一段简单中文语音，例如“二零二六年十一月十三日，第一百零一条”。日期取来源中的作品发布日期并转北京时间，不读下载时间或当前日期；缺日期时明确报“发布日期未知”。当前音频播放中勾选时，从原声当前进度继续，先补当前条提示；下条从头播放。当前条为定时重复文件时，按原声时长折算进度。
3. 15/30/60/90分钟设置继续可用。定时按整个媒体的播放进度计算，包含日期提示，暂停不计时；达到设定时长或播完本次序列即停止。换作品或定时设置重新计时，取消勾选恢复当前作品单曲模式。停止收听卸载音源；不自动改已学标记。
4. 开始时冻结元数据队列，按需准备当前和临近后续音频，不遍历读取全库原文、批量转写或预先合成全库。播放期间新入库作品留待下次开始。原视频、原文、评论、来源、已学库与通知均不修改，不重新下载/识别视频，不产生付费模型调用。

## 媒体实现

- iPhone 复用原生 audio 的 HLS 播放；服务端提供只追加的 EVENT 清单及6秒左右的TS分段，日期提示与原声使用 discontinuity 分隔，末尾追加 ENDLIST。让媒体时间线自己推进，减少锁屏后依赖页面 JavaScript 触发下一条的风险。
- 不原生支持 HLS 的浏览器按需导入 hls.js 1.7.4 Light，通过 MSE 播放；关闭 Worker，只允许同源源文件。AAC 优先；缺 AAC 而有 MP3 MSE 的 Chromium 使用 MP3。正常 iPhone 不需要下载该后备脚本。现有单曲/重复音频接口保持原行为。
- 作品区刷新时维持同一个 audio 节点；Media Session 保留播放、暂停、停止、定位。顺序模式锁屏标题使用“模型先生·顺序收听”，日期与序号以实际声音为准，避免把后台可能停止刷新的标题当成当前作品；前台按播放位置读取精简状态更新标题。视频开始暂停音频，音频开始暂停视频。
- 认证接口为 `/media/model-mr/audio-queues/<token>/index.m3u8`、`segments/<n>.ts` 和 `/api/model-mr/audio-queues/<token>/state`。全部在查找或生成前验证主人会话；清单 private/no-store，分段沿用私有 Range/HEAD，SW继续跳过媒体/API。状态仅含当前作品ID、标题、日期、序号、媒体位置与计数，不暴露内部路径。CSP只新增媒体 `blob:` 以支持MSE，没有放开脚本或外部连接。
- 会话令牌为128位随机值，仅内存保存最多8个、闲置6小时淘汰；不是新账户、数据库或长期观点记忆。服务器重启或会话失效后需重新点播放。媒体网络仍须保持，不承诺系统终止网页或断网后持续收听。

## 中文语音、缓存与许可证

- 复用小型 eSpeak NG 普通话语音，不使用大型模型、浏览器 speechSynthesis、额外付费服务或语音识别。认证后的首次顺序播放才从固定 PyPI URL 下载约10MiB、SHA-256锁定的运行库到 Git 外模型资料根 `audio-tools/`；后续离线复用。部署目标为既有 Linux x86_64，不需要全局 pip、系统组件、root或systemd变更。
- 包载体 espeakng-loader 0.2.4 包装层MIT，其附带实际引擎为GPL-3.0，不能混同。运行库附完整COPYING及精确引擎/载体源码链接；hls.js为Apache-2.0，前端公开同源完整许可证与版权声明。精确提交、路径、哈希及运行验证见复用报告，不修改六个正式上游的锁定版本。
- 下载/解包分别最多12/32MiB，校验路径与符号链接、临时目录原子替换；中文合成在15秒限时的短进程执行，最多20秒输出。语音失败时停止顺序准备并明确允许重试/改单曲，不能悄悄删掉日期提示后称为成功。
- 新缓存 `audio-cache/sequences` 独立限制512MiB、单件128MiB、30天按需淘汰，只删除符合格式的已知派生文件，近期使用项受保护。既有单曲512MiB不变，两者合计约1GiB，另加约20MiB运行库；空间不足明确报错。正在播放的已淘汰旧分段可按冻结配方重建。原媒体和未知文件不参与淘汰；派生文件及运行库均不进入Git或公开目录。

## 回滚
