# ADR-0044：模型先生新作品分阶段抓评与作者点赞修订

- 状态：`ACCEPTED / PARTIALLY_IMPLEMENTED`
- 日期：2026-09-09
- 决策者：产品所有者

## 背景

北京原模型下载器目前负责模型先生作品与公开评论；同机的北京博主采集器只读其
SQLite 和已下载媒体，再通过既有签名 outbox 把修订送到新加坡即时 AI。所有者要求
新作品刚发布后的评论更新更及时，同时必须准确保留“模型先生赞过某一条粉丝评论”
这一独立状态。

公开仓库当前只包含北京博主采集器及只读 `ModelDownloaderBridge`。原模型下载器的
抓取调度、数据库写入程序和 systemd 单元不在本仓库，也不在现有 Git 发布白名单内。
因此不得把普通博主采集器误当成模型先生下载器，或绕过现有边界直接写
`/var/lib/model-downloader/library.sqlite3`。

## 决定

1. 每部模型先生作品以抖音实际 `published_at` 计算年龄；从发布时间起未满 24 小时，
   评论刷新目标间隔为 15 分钟；满 24 小时后改为 60 分钟。边界固定为
   `age < 24h => 15m`、`age >= 24h => 60m`，不得按下载时间重新起算 24 小时。
2. 调度以“上一次成功完成评论抓取的时间”计算下一次到期；失败不得推进成功游标，
   同一作品不得并发执行两个评论任务。进程重启后应从持久状态恢复，已经超期的作品
   进入串行队列，不并发启动多个 Chromium。
3. 每轮评论合并必须更新评论正文、普通点赞数、回复数、父级/根级/回复目标关系、
   作者身份、公开标签、采集时间和作者点赞三态。`is_author_digged` 的
   `true / false / null` 分别代表已确认赞过、已确认未赞、来源未提供，禁止把 `null`
   当成 `false`，也禁止只按作者昵称猜测。
4. 即使评论正文、评论数和视频 `updated_at` 没有变化，只要作者点赞、普通点赞、
   回复关系或其他可见评论字段发生变化，也必须形成新的传输 revision。作者取消点赞
   同样是一项有效修订，不能被历史 `true` 覆盖。
5. 成功抓取后，变化应立即提交给现有数据库/发送链路。北京只读桥保持 15 秒检查，
   复用现有 HMAC、nonce、摘要、幂等、退避和回执；不新建公网端口、第二套 Token、
   第二个 MCP 或第二条新加坡资料通道。评论快照无变化时不制造重复业务 revision。
   指纹算法升级时，旧状态只有在旧签名仍匹配、且评论采集时间不晚于上次入队时间时
   才能原地迁移；最近 48 小时作品固定做一次当前快照重建，其他证据不足或确有更新的
   作品也按真实新 revision 发送。这样覆盖当前活跃作品，又避免升级本身触发数百条历史
   媒体全量重传。
6. 新加坡模型先生投影必须让规范化顶层 `author_liked=false` 覆盖旧
   `raw_json.author_liked=true`，保证作者取消点赞也能正确显示；页面与 MCP 继续只输出
   脱敏后的作者互动，不输出粉丝账号标识或原始 JSON。
7. 实施分两段：
   - 本仓库立即完成桥接修订指纹和新加坡显式取消点赞覆盖，并以合成数据回归；
   - 原模型下载器中的 15/60 分钟调度必须在其真实源码和运行单元被安全接入后实施、
     测试和发布。现有 `beijing-production` 只发布 `blogger-collector`，不得声称推进该
     分支已经修改原模型下载器。

## 验收

- 23 小时 59 分 59 秒的作品使用 15 分钟间隔；24 小时整及之后使用 60 分钟间隔。
- 失败不推进成功游标；重启后超期任务可恢复；同一作品无并发抓取。
- 只有 `is_author_digged` 从 `true` 变 `false`、或从 `false/null` 变 `true` 时，即使视频
  行与评论总数不变，也生成更高传输 revision。
- 北京评论包保留 `author_liked` 三态；新加坡收到显式 `false` 后页面不再显示“作者赞过”。
- 每次成功且有变化的抓取在桥接检查与现有发送器周期内入队；发送失败沿用 outbox
  重试，不丢本地抓取结果。
- 完整测试、敏感文件检查与相应生产健康检查通过；测试不得访问真实抖音、调用豆包或
  写生产数据库。

## 发布与回滚

- 当前开发只提交 `main`，不推进即时 AI 或北京生产，直至所有者明确要求正式发布。
- 桥接/新加坡部分可分别使用各自既有受限发布流程回滚；原模型下载器调度只能通过其
  已核实的真实维护流程更新。回滚不得删除评论、媒体、outbox 或主人整理内容。
