# ADR-0042：模型先生传输评论关系修复

- 状态：`ACCEPTED`
- 日期：2026-09-08
- 决策者：产品所有者要求即时 AI 的作者互动完整显示粉丝原提问与模型先生回复

## 背景

北京模型下载器页面能够把模型先生回复与粉丝原问题放在同一楼层。代码核对确认，北京只读桥和 `blogger-transfer/v1` 评论包已经同时发送粉丝评论、作者回复，以及顶层 `parent_source_comment_id`、`root_source_comment_id` 和 `reply_to_comment_id`。新加坡接收器也完整验证并保留这 21 个白名单字段。

缺口位于即时 AI 的模型先生投影：`ModelMrClient._clean_comment()` 只从旧本地快照的 `raw_json` 读取父级/根级关系，没有读取北京传输包顶层字段。传输评论没有 `raw_json`，因此每条评论按行号生成不同的脱敏线程键，作者回复也被当成顶层评论。作者互动页据此只能展示红色作者回复，找不到同楼粉丝原问题。评论总数没有减少，问题不是北京漏采、漏传或新加坡接收丢包。

## 决定

1. 模型先生清洗层同时兼容旧 `raw_json` 和 `blogger-transfer/v1` 顶层关系字段。线程优先使用根评论编号，其次使用父级、旧线程字段、回复目标和自身编号；随后只保存 12 位 SHA-256 脱敏线程键，不向页面或 MCP 返回来源评论编号。
2. 只要存在父级关系，清洗结果至少标记为一级回复。粉丝根评论和模型先生回复因此进入同一线程；手机“作者互动”和只读 MCP 作者回复工具共同恢复原提问上下文。
3. 新导入作品在 Git 外 `beijing-transfer-map.json` 记录评论投影版本 2。旧映射没有版本时，服务器启动后台只读当前、已完整验证的保留评论包，并按完全相同的脱敏清洗规则重建评论线程。
4. 旧数据修复必须满足映射作品版本与当前验证传输版本完全一致。修复只替换该作品的脱敏评论数组和评论计数，保留主人标题、正式原文、转写、解读、关键词、评股和视频；不复制视频、不重新发送北京数据、不创建处理任务、不调用 ASR、豆包或其他模型。失败项不打完成标记，下次启动可安全重试。
5. 北京模型下载器、北京数据库、采集规则和传输协议不修改。既有协议测试继续证明父级/根级关系进入压缩评论包；本修复只进入即时 AI 新加坡应用代码。

## 未采用的方案

- 不让北京重新传输全部模型先生视频和评论。原验证评论包仍在新加坡，强制重传会浪费带宽并引入不必要的新版本。
- 不根据作者回复中的昵称或正文猜测粉丝问题。只有采集端明确的父级/根级编号可以建立线程关系。
- 不把原始评论编号发送到浏览器或 GPT。它们仅在服务器内存中用于生成不可逆线程键。
- 不只修复前端排版。关系已经在投影阶段丢失，前端无法从两个无关联的脱敏对象可靠恢复。

## 影响与退出条件

- 版本升级为 0.21.3 候选，尚未正式发布；生产继续运行 0.21.2。
- 验收已覆盖北京顶层关系字段导入、旧映射无付费重建、主人内容不覆盖、手机线程分组和 MCP 原提问返回；即时 AI 183 项、北京 218 项、前端 7+6 项、生产构建和高危审计通过。
- 正式发布后应抽查所有者截图对应作品：作者互动仍为 3 组，每组先显示粉丝提问，再显示模型先生红色作者回复；评论总数不应改变。
