# ADR-0053：模型先生图文作品的原图、正文与私有投影

- 日期：2026-09-16
- 状态：`ACCEPTED / IMPLEMENTED_LOCALLY / NOT_RELEASED`
- 目标版本：北京模型下载器 `0.10.0+git.image-posts`；即时 AI `0.23.0`
- 决策者：产品所有者

## 背景与根因

模型先生下载器原先把作品等同于视频：主页只查询 `/video/` 链接，解析器只寻找 MP4，SQLite 只保存一个 `file_path`，北京只读桥又固定生成视频清单。模型先生发布 `/note/` 图文时，作品卡在主页扫描阶段就被忽略；即使手工补入记录，后续数据库、传输、新加坡投影和手机页面也没有多图媒体模型。

2026-09-16 对最新版代码与生产只读状态的核对确认：生产模型下载器为 `0.9.2+git.video-priority-3m`，现有 37 条作品记录均为视频地址，没有可用于真实验收的图文记录。缺口是端到端作品类型契约，不是某一张图片下载失败。

## 决定

1. 模型先生主页扫描同时接受 `/video/<id>` 和 `/note/<id>`，并把后者规范化为 `work_type=image`。三分钟新作品硬优先、全天运行、评论空档和失败重试规则不变。
2. 图文解析从公开作品页的页面状态和已加载 JSON 中取得完整公开正文及有序图片列表。正文首个非空行可作为标题；没有正文时保留明确的“抖音图文_编号”占位标题，不冒充抖音原题。
3. 图文下载保存按发布顺序排列的全部原图，只接受通过文件头验证的 JPEG、PNG 或 WebP；响应声明的扩展名与实际格式不同时以实际格式为准。取消、解析失败、数据库写入失败或修复失败时清理新文件并恢复旧完整图片组，不把半套图片标记为完成。
4. 北京运行数据继续在 Git 外保存：视频位于 `/srv/model-downloader/videos`，图文原图位于 `/srv/model-downloader/images`。SQLite schema 由 4 增至 5，给 `videos` 加入 `description`、`work_type`，并新增有序 `work_media` 表保存每张图片的路径、MIME、大小和 SHA-256。升级是加列/加表；旧视频默认仍为 `video`，不重写媒体和评论。
5. 管理页统一称为“作品库”，可查看完整图文正文、逐张预览/下载原图、补抓评论、修复和删除。所有图片路由继续要求主人登录并强制限制在图片根目录内；删除一条图文时以可恢复暂存方式同时删除其全部已登记原图和评论。
6. 北京桥继续只读模型下载器数据库和已完成媒体，不访问抖音、不启动浏览器。它复用既有 `blogger-transfer/v1` 的 `image/gallery` 能力，把完整正文与所有有序原图作为同一修订发送；旧视频的签名结构保持不变，避免升级导致历史视频批量重传。
7. 新加坡投影版本增至 3，复核每个已验证 artifact 后，把图文正文和多张原图写入独立 Git 外模型先生资料根。手机作品卡和详情显示“图文/原图数量”、公开正文与响应式原图库；图片只通过主人认证的私有 API 提供，不进入静态目录或 MCP 二进制结果。
8. 图文没有视频音轨，因此不建立自动 ASR/关键词处理任务，也不消耗豆包调用；视频送达自动处理保持原样。现有评论、标题、关键词、解读、评股、投资思路和主人编辑优先级继续保留。
9. MCP 只读作品元数据增加 `work_type`、`image_count` 和公开正文，明确原图只在主人登录页面提供；不返回服务器路径、文件名、摘要、原始 JSON 或图片二进制。

## 文字识别边界

本决定中的“图文正文”指抖音作品公开描述文字，与原图一同保存和展示。它不对图片像素中的文字自动做 OCR，也不把 OCR 猜测写入公开正文。若以后需要图片内文字识别，应另行决定证据来源、人工核对、费用和覆盖规则，不能静默混入本链路。

## 兼容、安全与发布边界

- `blogger-transfer/v1` 原本已允许 `video`、`image`、`gallery` 及 JPEG/PNG/WebP，本次不新增公网端点、凭据、scope、数据库直连或第二套传输协议。
- 新快照读取继续兼容版本 1、2；版本 3 只增加作品类型和媒体列表。旧客户端仍能读取标题、正文、评论等已有字段，旧视频接口和 Range/HEAD 行为不变。
- 原图、数据库、评论、传输 artifact、浏览器资料、Cookie、密钥和日志均在 Git 外；测试只使用临时合成图片和数据。
- 本轮用户要求先核对并优化最新版，没有给出“正式发布”口令。因此只在 `main` 形成候选，不推进 `beijing-production`，不调用北京或新加坡发布器，不重启生产服务，也不触发真实采集、ASR、豆包或 AI。

## 验收

- 模型下载器 18 项回归通过，覆盖 `/video/`/`/note/` 识别、嵌套图文正文与顺序、schema 4→5 无损迁移、多原图摘要及同大小损坏检测。
- 北京采集/传输 221 项回归通过，证明单图/多图清单按序生成、正文安全规范化、旧视频桥接行为和部署契约不回退。
- 北京统一部署控制 32 项回归通过，证明套件清单、检查脚本和两组件发布门禁保持收口且仍为人工触发。
- 即时 AI 202 项回归通过，证明完整 gallery 经签名传输后投影、私有图片读取、MCP 元数据、旧快照/视频兼容，以及图文不建立视频处理任务。
- TypeScript/Vite 0.23.0 生产构建、静态资源逐字节一致、Python 编译、npm 高危依赖审计和 `git diff --check` 通过。

## 回滚

回滚应用代码只停止发现和投影新的图文。schema 5 的加列、`work_media` 表和已保存原图保持原位，不降级数据库、不删除图片、不改写旧视频或评论；旧代码会忽略新增字段。已经投影到新加坡的图文继续作为主人资料保留，除非主人在现有管理界面明确删除。
