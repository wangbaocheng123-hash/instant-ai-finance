# 项目记忆与断点续作协议

## 为什么不依赖聊天记忆

聊天上下文可能被压缩、切换或结束。真正可靠的项目记忆必须是仓库中的可读文件，并且每次开始先读、每次结束再写。

## 三层记忆

| 层级 | 文件 | 作用 | 变更频率 |
|---|---|---|---|
| 永久规则 | `AGENTS.md`、`PROJECT_CHARTER.md` | 身份、边界、启动和收尾协议 | 很低 |
| 当前状态 | `STATUS.md`、`TASKS.md`、`UPSTREAM_LOCK.yaml` | 走到哪一步、下一步、版本锁定 | 每个任务 |
| 证据历史 | `CHANGELOG.md`、`docs/decisions/`、`research/` | 为什么这样决定、依据是什么 | 随成果追加 |

## 启动恢复

每次新任务进入仓库后：

1. 读取 `AGENTS.md` 规定的文件顺序。
2. 从 `STATUS.md` 找到 `当前阶段`、`最近完成` 和 `下一项唯一建议任务`。
3. 在 `TASKS.md` 找到对应任务编号、依赖和验收条件。
4. 若研究上游仓库，先核对 `UPSTREAM_LOCK.yaml` 的仓库、提交和状态。
5. 只读取与本任务有关的报告，不把未验证假设当成结论。
6. 开始前用一句话说明本轮从哪个检查点继续。

## 工作中记录

- 每个可独立验收的工作使用稳定任务编号，例如 `R0-TR-STATIC-01`。
- 状态仅使用 `NOT_STARTED`、`IN_PROGRESS`、`BLOCKED`、`DONE`。
- `DONE` 必须附验收证据；文件存在不等于研究完成。
- 阻塞必须写明原因、已尝试事项、所需授权和不受阻塞影响的并行工作。
- 研究结论引用固定提交，不能只引用默认分支的浮动内容。

## 收尾检查点

每次会改变项目状态的任务结束时：

1. 把已完成事实写入 `CHANGELOG.md`。
2. 更新 `TASKS.md` 的任务状态和证据链接。
3. 将 `STATUS.md` 压缩为一页左右的最新快照；不要在其中堆积历史。
4. 明确一项且仅一项 `下一项唯一建议任务`。
5. 重大决定新增 ADR，不覆盖旧 ADR；若推翻旧决定，用新 ADR 标记替代关系。
6. 用 `scripts/check-project-memory.ps1` 检查必需文件、H 盘路径和 Git 泄漏风险。

该脚本还必须校验 ADR-0003 的永久单人边界：产品只能是单机单用户、无账户体系，且不得为注册、登录、姓名/邮箱资料、团队、角色、权限、租户或用户偏好中心预留 schema/API。

## 防漂移规则

- 原始总指令保存在 `docs/FOUNDATION_DIRECTIVE_R0.md`，不得静默删减。
- `AGENTS.md` 应保持短而有约束力；研究细则放在专题文档。
- 已验证事实、待验证假设和用户决定必须使用不同标记。
- 如果新请求改变长期目标，先指出影响，再更新章程、ADR、路线图和状态文件。
- 如果仅是一次性偏好，不写入永久规则。
