# 北京采集端与新加坡智能端拆分方案

## 目标边界

```text
公开抖音主页
  -> 北京采集端（串行 Chromium）
     -> 视频/图文、评论、楼中楼、作者回复/点赞、确定性分类
     -> 持久化 outbox + HMAC 签名 + SHA-256
  -> 新加坡即时 AI 现有应用（同仓库、业务数据隔离）
     -> 按稳定博主 ID 幂等入库
     -> 豆包转写、标题、关键词、内容解析和知识库
     -> 单主人手机入口与受控 GPT/MCP 查询
```

北京无需被 GPT 或公网主动访问；它只向新加坡的 HTTPS 接收接口发起出站请求。即时 AI 的财经新闻库、博主资料库和时变罗盘数据库不得互相合并。

北京原模型下载器继续作为独立服务运行，本方案不清理或替换它。新增博主采集服务使用独立目录、配置、数据库和 service，并与模型下载器错峰调度。新加坡实现只进入即时 AI 现有 `instant-ai-finance` 仓库，不建立第二个应用仓库。

## 部署角色

### 北京：collector

- 与原模型下载器并存，不读取、迁移或修改其运行数据；两套服务的浏览器任务必须错峰。
- 多博主主页轮替扫描，同一时刻最多一个 Chromium。
- 下载公开视频/图文并校验媒体完整性。
- 抓取公开评论、楼中楼、作者回复和作者点赞标记。
- 执行不调用模型的确定性分类与低价值过滤标记。
- 评论 bundle 只输出 v1 字段白名单，不传 `author_uid`、`sec_uid`、`user_id`、`raw_json` 或本机路径。
- 媒体在进入 outbox 前按 v1 role×MIME 白名单过滤；仅发送 MP4 与 JPEG/PNG/WebP，其他类型计入明确诊断。
- 每个作品形成一份版本化清单，写入持久化 outbox。
- 先发送清单，按接收端返回的缺失项流式传输媒体，最后请求完成确认。
- 失败使用指数退避；只有收到接收回执才标记完成。

### 新加坡：intelligence

- 代码直接属于即时 AI 现有仓库和现有发布版本，本仓库只记录跨端协议，不复制新加坡实现。
- 使用独立内部接收接口，不复用主人网页登录 Cookie。
- 校验时间戳、nonce、正文哈希和 HMAC；nonce 在有效期内只能使用一次。
- 以 `(platform, creator_id, source_work_id)` 幂等更新，保留最新采集版本。
- 媒体先进入临时区，长度和 SHA-256 全部通过后原子移入正式目录。
- 完整作品进入任务队列，串行执行豆包转写以及后续解析。
- 对外手机页面与 GPT/MCP 仍走即时 AI 的单主人认证。

## 传输状态机

```text
pending -> manifest_accepted -> media_uploading -> finalizing -> delivered
   |              |                   |              |
   +---------- retry_wait <-----------+--------------+
                         -> dead_letter（达到人工检查阈值）
```

网络超时不代表接收失败。北京必须使用同一 `transfer_id` 查询或重试；新加坡对同一 `transfer_id` 返回相同结果，不能建立重复作品。

## 身份与版本

- `creator_id` 是跨服务器稳定标识，不使用可修改的博主显示名作主键。
- `source_work_id` 使用平台公开作品 ID。
- `transfer_id` 由清洗后的作品、评论和媒体清单规范化 JSON 计算 SHA-256；评论更新会产生新的版本，但仍更新同一作品。
- 协议首版为 `blogger-transfer/v1`，未知主版本必须拒绝，不能猜测字段。

## 媒体策略

第一版支持新加坡 HTTPS 流式接收；接口不得整文件读入内存。传输契约只接受 `video`+`video/mp4`，以及 `image`/`cover`+`image/jpeg|image/png|image/webp`；不支持 `audio/mpeg`、`audio/mp4`、`application/mp4` 或 `application/octet-stream` 兜底。若后续视频量明显增加，可把媒体适配器替换为阿里云 OSS：北京上传对象，新加坡接收清单并拉取，业务契约保持不变。

## 分阶段实施

1. 固定清单、签名、幂等和脱敏测试。
2. 北京接入持久化 outbox，并在每条作品/评论同步完成后排队。
3. 新加坡增加隔离接收库、临时媒体区和内部鉴权。
4. 接通豆包转写与标题/解析任务，复用即时 AI 已有单主人展示。
5. 增加手机端多博主入口和端到端状态。
6. 北京采集源码单独建立检查点；新加坡随即时 AI 现有仓库发布。先用无真实媒体的模拟包验收，再选择一条公开视频试运行。
