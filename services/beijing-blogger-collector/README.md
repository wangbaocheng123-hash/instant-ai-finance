# 北京博主智能采集器

本目录是公共仓库 `instant-ai-finance` 中的北京旁路采集服务安全快照；新加坡的接收、识别、整理、知识化和手机访问继续由即时 AI 主应用负责。北京原模型下载器保持不变，与本服务独立并存。

1.0.8 接入“北极采集器”PWA/Apple 图标和严格的 `/health/version` 部署身份接口，并切换到 `beijing-production` 专用生产分支。普通 `main` 推送不会自动上线；正式发布与回滚规则见仓库根目录 `docs/BEIJING_COLLECTOR_GIT_RELEASE.md`。

## 系统边界

```text
北京 collector
  视频/图文下载 + 评论/楼中楼 + 作者互动 + 规则分类
  -> HTTPS/HMAC + 持久化 outbox + SHA-256
新加坡即时 AI（现有仓库）
  独立博主资料库 + 豆包转写 + 标题/关键词/解析 + 手机/GPT 查询
```

- 时变罗盘完全独立。
- 即时 AI 的财经新闻数据库完全独立。
- 模型先生资料库与其他博主资料按稳定博主 UUID 隔离。
- 北京只主动向新加坡发起出站请求，不向 GPT 暴露采集服务。
- 北京管理中心长期保持“仅手动采集”，只有所有者明确点击或要求采集一次时才启动 Chromium；同一时刻最多运行一个 Chromium。
- 所有博主共用同一个所有者抖音登录会话；每位博主的主页设置、作品、评论和同步游标仍然独立，不要求新增一位博主就重新登录一次。
- 北京原模型下载器不清理、不迁移；部署时与本采集服务错峰运行，避免两个 Chromium 同时启动。
- 原模型下载器已经下载完成的“模型先生”视频与评论由只读桥接器写入同一持久 outbox，复用博主通道的 HTTPS/HMAC、摘要、幂等、退避与回执；桥接器不启动 Chromium，新加坡按保留身份把资料放入独立模型先生作品库，不混入博主列表。
- Git 只保存源码、测试和部署模板，不保存媒体、评论数据、Cookie 或密钥。

详细设计见 [北京—新加坡拆分方案](docs/architecture/beijing-singapore-split.md)。

## 北京采集端

1.0.7 增加“指定一条视频”：在某位博主的采集设置里粘贴完整抖音分享文案或视频链接，
自动识别作品编号，然后点击“只抓取这条视频”并确认。该任务只处理这条视频，
沿用当前博主的评论设置和北京到新加坡的传输流程；已下载的视频不会重复下载，
可单独补抓它的评论。链接仅用于本次操作，重新打开设置时清空。
粘贴链接本身不会启动 Chromium，按数量抓取的条数设置保持原值。

北京端负责：

- 扫描多个抖音博主的公开主页；
- 下载公开视频和图文原图，兼容音视频分离资源；
- 抓取主评论、楼中楼、作者本人回复和作者点赞标记；
- 做不调用模型的结构分类和低价值标记；
- 把每次作品快照写入 SQLite outbox，断网后继续重试；
- 分阶段传输清单、评论包和媒体，收到新加坡回执后才完成任务。

轻量依赖位于 `requirements-collector.txt`。正式服务器通过 `BLOGGER_AGENT_ROLE=collector` 启动，不加载 OpenAI、豆包、知识库或 MCP 模块。

北京端同时提供只监听 `127.0.0.1:18797` 的轻量管理中心。通过受控 SSH
端口转发访问后，可以查看本地作品、媒体、评论分类和北京到新加坡的传输状态，
并手动触发一次采集或提前重试待传任务。打开页面、刷新页面、更新程序和重启管理
服务都不会自动采集；媒体只在打开作品详情时按需分段读取。

## 新加坡即时 AI 模块

新加坡端不是本仓库的第二个部署角色，也不建立新仓库。它直接在现有 `instant-ai-finance` 仓库中作为独立业务域运行：

- 接收并验证北京节点的 HMAC 请求；
- 以博主 UUID、平台和作品 ID 幂等归档；
- 媒体先写临时文件，校验长度和 SHA-256 后原子入库；
- 排队执行豆包转写、标题编辑、关键词和内容解析；
- 通过即时 AI 现有单主人登录保护手机页面；
- 通过受控接口向 GPT 提供已经归档的博主资料。

### GPT 云端原文查询

本地博主 MCP 会继续查询原有 Windows 历史知识库，同时按用户请求即时查询新加坡即时 AI 中已经接收的最新博主作品。云端记录以 `cloud-video:<作品键>` 返回，原有 `get_model_knowledge` 和 `get_video_original` 可以读取其正式视频原文；没有正式原文时只会返回明确标记为未确认的识别文字。

- 不复制新加坡数据库、评论或视频到本机，也不设置后台轮询。
- 新作品完成北京→新加坡传输并保存原文后，下一次 MCP 搜索自然可见。
- 云端不可用时，本地历史知识检索保持可用。
- 独立机器凭据不得写入 `.env`、Git、日志或命令参数。服务器使用 root `0600` 文件；本机由 `scripts/provision_instant_ai_cloud_mcp.ps1` 生成并保存当前 Windows 用户的 DPAPI 密文。
- 正式配置脚本只可在即时 AI 0.18.0 已通过受限发布器上线后执行；脚本不会输出凭据值。

在所有者明确批准自动计费策略前，新视频只进入 `awaiting_asr_approval`，不会自动产生豆包费用。

## 本地开发

完整开发环境：

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p "test_*.py"
python -m mx_agent.server --host 127.0.0.1 --port 8797
```

北京角色配置模板为 `.env.collector.example`。真实 `.env`、`config/settings.json`、`config/creators.json`、数据库、浏览器资料和媒体目录都被 Git 忽略。

## 实施顺序

1. 固定传输协议、签名、幂等、乱序保护与脱敏测试。
2. 接通北京串行采集和持久化 outbox。
3. 在即时 AI 中建立隔离的新加坡接收库和媒体临时区。
4. 用模拟作品完成端到端传输，不调用真实豆包。
5. 增加手机端多博主入口和人工确认的豆包任务。
6. 为本仓库建立北京采集源码检查点；新加坡代码继续使用即时 AI 现有 Git 远程和发布流程。
7. 最后选择一条有权访问的公开视频做真实链路验收。
