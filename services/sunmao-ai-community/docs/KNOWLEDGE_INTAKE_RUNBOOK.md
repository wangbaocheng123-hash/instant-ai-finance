# 新加坡云端 Codex 接收榫卯资料操作手册

状态：分类和操作契约已确定；0.3.9开发候选已有统一知识表、受控图片导入器与公开只读尺寸API，但正式知识后台、远程上传/审核、通用检索、备份恢复和北京生产发布尚未完成。适用于所有者通过手机向新加坡云端 Codex 提供新的链接、文字、尺寸、图纸、3D 模型或视频。

## 先判断当前可以写到哪里

读根目录 `STATUS.md`、`TASKS.md` 和社区 `README.md`，以代码与实际接口核对完成度：

| 当前能力 | 可执行的动作 | 不可声称的结果 |
| --- | --- | --- |
| 已有 `web/size-resources.json` | 将所有者明确指定的尺寸参考外链按现有安全格式追加，经测试后形成代码候选 | 已把文章全文或尺寸导入知识库 |
| 已有 `web/videos.json` | 核实属于同一合集的精确集数、标题、封面和原链接后更新索引 | 已下载视频、转写内容或理解全部工艺 |
| 0.3.9开发候选的图片导入器 | 在本地临时库用已确认标题和原图验证类型、大小、摘要、随机存储键及公开读取；形成可审查代码候选 | 已写入北京知识库、已上线图集、已开放手机上传 |
| 尚无正式知识录入后台 | 整理可审查的条目草案、开发后台与云端数据底座 | 已将 PDF/3D/视频文件放入北京知识库 |
| 后续后台真正上线 | 通过单主人受保护的录入、审核和发布接口写入北京资料库，回读稳定 ID、状态、公开页面 | 仅凭请求成功就断言公网可见 |

当前静态清单属于代码发布包；代码候选要测试并进入 `main`。只有收到根目录规定的社区发布指令才能推进 `sunmao-production` 并上线。未来后台中的普通资料发布由所有者的“加入/发布这份资料”请求授权，不需要为每条资料重启服务；后台未上线前不能用手工 SQLite 写入代替。

## 固定分类法

类目以 `config/knowledge_taxonomy.v1.json` 为唯一机器可读列表。每个知识主题恰有一个 `primary_topic`，可以关联多种 `resource_kinds`、多个来源和多条资源。例如“某种榫卯结构”作为一个主题，可同时挂尺寸、图纸、3D 模型、视频和说明。不要为每种文件复制一份互不关联的主题条目。

先判断资料主要讲什么：结构、器物家具、制作过程、工具材料或原理文化；再判断给了什么：尺寸值、尺寸参考链接、图纸、3D 模型、视频、图片或文章。主题不明确时仅存草稿并使用 `unclassified`。网站“尺寸型”可展示已核实尺寸或所有者指定的尺寸参考外链；“榫卯108道”只展示已核对的合集集数。资料可同时出现在多个页面视图，但只有一个主题 ID。

## 每次资料接收的九步

1. **记录原始输入。** 区分所有者直接写出的事实、所有者给的外链、可读取文件和 AI 推断。保存精确来源 URL/文件标识及提供时间；禁止把凭据或私人原件写入 Git。
2. **核对可读取性。** 访问受限、页面触发验证、视频没有字幕或 3D 文件缺单位时，明确记录“无法核实”的字段。不得绕过来源限制，也不得凭标题猜内容。
3. **查重。** 先按稳定条目 ID、规范化的精确 URL、合集 ID+集数或文件摘要查已有资料；同一主题的新资料优先建立关联和新版本，保持旧链接与来源记录。
4. **归类。** 按 taxonomy 选择一个主题和全部适用资源形式；写下选择理由。歧义只影响尚不确定的字段，已确定的原链接仍可保存为候选。
5. **提取事实。** 尺寸记录“部位、数值或范围、单位、适用条件、来源定位”；3D 记录格式、单位/比例（若可核实）、原件与预览关系；视频记录合集、集数、原链接、可核实的标题和有来源的时间点。
6. **标注状态。** 所有者明确给出的数字可以按“所有者提供”记录；工具从文件读出的数字要有定位和单位；AI 推断的数字保留为待核实草稿。来源或公开权限不明的文件不发布。
7. **选择写入路径。** 现阶段只走符合现有约束的静态外链候选；正式后台上线后走其受保护 API。二进制文件只进北京社区 Git 外云端存储，不进新加坡即时 AI 数据目录、仓库或本地电脑正式库。
8. **验证结果。** 检查字段、URL、重复项、展示类目、权限和关联关系；后台上线后用稳定 ID 回读，再从两个社区域名验证公开可见性。资料撤回也必须停止公开检索和资源访问。
9. **向所有者汇报。** 报告“收到什么、归入哪个主题、关联哪几种资料、哪些尺寸已经核实、存入哪里、当前状态、仍缺什么”。`已整理`、`main 已更新`、`北京知识库已写入`和`公网可见`必须分别报告。

## 条目草案字段

下面只是字段示例，不是实际资料，也不能作为公网数据：

```yaml
schema_version: 1
item_id: "待分配或现有稳定ID"
title: "所有者提供或来源核实的标题"
primary_topic: joint_structure
resource_kinds: [measurement, model_3d, video]
summary: "只写可从来源核实的描述"
source_kind: owner_supplied
source_ref: "原始链接、文件标识或所有者提供记录"
measurements: []  # 每项必须另记部位、值、单位、适用条件、出处
related_item_ids: []
review_state: draft
```

资料的正式数据字段以云端数据库迁移为准；此草案帮助新智能体在数据库尚未建成时一致地整理信息，不允许把用户原件或草案原文提交到公开 Git。

## 什么时候需要问所有者

仅在事实或公开范围无法判断时简短询问，例如“这份模型的单位是毫米还是厘米？”、“这段视频是否为你拥有并允许社区托管的原片？”或“这篇文章应列为尺寸参考还是工艺说明？”。能够从原文、所有者明确文字和现有资料核实的内容，直接归类并继续操作，不重复请求同一授权。
