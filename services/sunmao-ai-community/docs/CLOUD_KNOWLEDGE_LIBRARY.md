# 榫卯 AI 社区云端知识库布局

状态：0.3.9已在北京生产实施版本1表结构、首期图片原件目录和公开只读资源访问；受保护上传/审核、通用检索、AI问答及备份恢复演练尚未完成。

## 目标与运行位置

社区访客只向云端社区服务请求资料。所有正式知识条目、检索索引和允许公开的文件都由北京的 `sunmao-ai-community.service` 及其云端存储提供；所有者电脑和 Obsidian 均不参与在线请求。`https://amuyeye.com/` 仍通过现有新加坡隧道访问北京同一服务和数据，不建立第二份知识库。

代码继续放在原子发布目录 `/opt/sunmao-community/current`，可持久数据继续放在 Git 外的 `/var/lib/sunmao-community`。首次实现优先复用北京社区现有 SQLite 和受限数据目录，不为知识库建立另一套网站、账号、数据库或发布分支。后续媒体量明显超过单机磁盘与备份能力时，只把二进制对象迁入社区专用的云端对象存储；数据库中的稳定资料 ID、资源 ID 和访问 API 保持不变。

## 云端目录

```text
/var/lib/sunmao-community/
├── community.sqlite3                   # 现有交流/统计；新增知识目录和检索表
├── admin-username                      # 现有单主人凭据，保持原权限
├── admin-password.hash                 # 现有单主人凭据，保持原权限
└── knowledge/
    ├── incoming/<upload-id>/           # 待校验的临时上传；不可公开访问
    ├── originals/                       # 经校验的原始文件；按类型和随机资源 ID 寻址
    │   ├── documents/<asset-id>/        # PDF、图纸等
    │   ├── images/<asset-id>/           # 原始图片
    │   ├── models/<asset-id>/           # 3D 原始文件
    │   └── videos/<asset-id>/           # 有权托管的自有视频；外站视频不复制到此处
    └── derived/<asset-id>/              # 可重建的封面、缩略图、网页预览和字幕
```

目录用系统生成的 `upload-id` 和 `asset-id`，不用访客输入、中文标题、原文件名或 URL 拼路径。资料分类和显示名称存在数据库中，调整栏目时不移动二进制文件。`incoming` 定期清理失败上传；`originals` 只有确认没有任何有效资料引用且备份完成后才能回收；`derived` 可从原件重新生成。后台文件接口按资料/资源 ID 鉴权并读取文件，不把整个数据目录映射为公开静态目录，不接受任意文件系统路径。

北京社区进程当前已被 systemd 限制只读发布目录、可写 `/var/lib/sunmao-community`。创建上述子目录时沿用 `sunmaocommunity` 所有权和受限权限；上传大小、文件类型、磁盘余量、内容校验、3D/媒体处理资源上限须在开放上传前确定。大文件转码和 3D 预览生成不得占用面向访客的同步请求。

## 一条知识的统一记录

知识库以“资料条目”为主，尺寸、结构说明、图纸、模型和视频可以关联到同一条目，而非各自形成孤岛。数据库至少区分以下概念：

| 记录 | 必要内容 | 用途 |
| --- | --- | --- |
| `knowledge_items` | 稳定 ID、类型、标题、别名、分类、摘要、正文、审核状态、版本、更新时间 | 查找与展示的主体 |
| `knowledge_measurements` | 条目 ID、部位、数值/范围、单位、适用条件、来源 ID、核实状态 | 精确尺寸；统一保留原始单位，展示时转换 |
| `knowledge_sources` | 来源类型、原始 URL 或资料标识、作者/提供者、授权范围、核实时间 | 给用户展示出处，区分事实与推断 |
| `knowledge_assets` | 资源 ID、条目 ID、文件种类、存储键、校验摘要、大小、公开级别、版本 | 找到图纸、模型、图片和自有媒体 |
| `knowledge_relations` | 主条目 ID、关联条目/视频 ID、关系类型 | 将尺寸、榫卯结构和视频互相连接 |

尺寸值必须带单位、部位、适用条件和来源；没有核实过的数字不能作为正式尺寸发布。3D 模型的原件和网页预览分别记录，AI 检索主要使用核实过的模型说明、几何属性和关联尺寸，不能凭文件名猜测结构。视频记录标题、原链接、经授权的字幕或人工说明、涉及工艺及时间点；只有标题和链接时只提供入口，不声称已理解视频细节。

现有 `web/videos.json` 的 34 条抖音作品以及 `web/size-resources.json` 的微信资料卡，先作为已发布外部链接索引保留。将来导入知识目录时保留来源 URL 和现有展示顺序，按资料 ID 建立关联；导入不能凭外链自动生成尺寸或偷偷复制第三方视频。本人有权托管的文件可进入云端 `originals`，第三方资料默认保存链接和经过确认的说明。

## 整理、发布和问答

1. 所有者通过受保护后台上传或填写资料。文件先进入 `incoming`，记录上传任务 ID；尚未审核的内容不进入公开检索。
2. 服务器校验文件并提取可用的文字与元数据；AI 可以生成标题、标签、摘要、尺寸候选和关联建议。候选需保留来源定位与原始值，特别是尺寸和材料等工程事实由所有者确认。
3. 确认后在数据库中发布新版本，再把合格文件放入 `originals`，生成可重建的 `derived`。检索索引只包含已发布版本；旧版本可追溯，撤回后立即停止公开检索和文件访问。
4. 访客输入问题时先按标题、别名、工艺词和结构化尺寸检索，返回可解释的资料卡。需要 AI 解答时，只向模型提供召回且可公开的资料片段及来源 ID；回答附资料链接，证据不足时明确说明。浏览器和访客永远不接触模型密钥或文件系统路径。

Obsidian 可以成为所有者编写草稿的可选编辑器。即使使用它，也要通过同一套校验、审核和发布流程把内容送入北京知识库；本地笔记本不是线上服务的依赖。

所有者通过手机交给新加坡云端 Codex 的新资料按 `KNOWLEDGE_INTAKE_RUNBOOK.md` 执行；正式类目和资料形式使用 `../config/knowledge_taxonomy.v1.json`。操作端先核对当前接口状态，不能把本节计划中的后台当作已上线能力。

## 备份、迁移与验收

- SQLite 目录数据与 `knowledge/originals` 属于同一恢复点，备份时记录目录版本和资源校验摘要；备份副本必须离开当前云盘，并定期抽样恢复。`incoming` 和 `derived` 不代替正式原件备份。
- 未来迁到对象存储时，只替换 `knowledge_assets` 的存储适配器/键，不改变资料 ID、公开 URL 或检索结果格式。迁移前后按摘要、数量、权限和随机样本核对，保留回滚窗口。
- 不依赖所有者电脑在线：关闭本地电脑后，公开资料卡、尺寸检索和已授权资源仍从云端返回；公开链接不能访问草稿、原始非公开文件或其他系统的数据。
- 发布知识库功能仍遵守社区 `main` → `sunmao-production` 的明确发布规则；创建生产目录、迁移数据和启用上传须在相应功能完成测试并获得发布指令后执行。

## 后续实施顺序

1. 数据表、目录初始化和备份/恢复测试。
2. 单主人后台的资料录入、文件校验、审核和发布。
3. 已发布资料检索、输入框资料卡，以及现有视频/尺寸外链关联。
4. AI 辅助整理与带出处的问答；随后再按需要加入自有视频和 3D 网页预览。
