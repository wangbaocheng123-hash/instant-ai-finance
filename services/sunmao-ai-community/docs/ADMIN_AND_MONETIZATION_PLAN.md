# 榫卯 AI 社区后台与商业化框架

## 产品原则

社区保持“小而美”：一个公开网站、一个管理后台、一个清晰的会员体系。先验证木友真正需要的内容和服务，再增加收费与广告；不建设与社区无关的通用大平台。

技术上继续采用模块化单体。访问统计、内容、交流、会员、订单和广告在代码中分模块，部署上仍是独立的 `sunmao-ai-community.service`，使用社区自己的端口、数据目录和备份流程，不触碰同机的北京博主采集器与模型下载器。

## 后台信息架构

| 后台模块 | 主要能力 | 当前状态 |
| --- | --- | --- |
| 数据中心 | 今日/累计访问、匿名访客、页面、来源、设备 | 第一版已完成 |
| 内容中心 | 榫卯 108 道、尺寸资料、文章、附件、上下架 | 下一阶段 |
| 交流管理 | 留言审核、隐藏、回复、举报、敏感操作记录 | 下一阶段 |
| 用户中心 | 账号、角色、状态、会员等级、用户资料 | 账号阶段 |
| 会员与订单 | 商品、权益、订单、支付、退款、到期时间 | 商业化阶段 |
| 广告与合作 | 广告位、素材、起止时间、展示/点击、合作方 | 商业化阶段 |

后台角色只保留所有者、内容编辑、社区管理员和客服。敏感操作应记录“谁、何时、改了什么”，支付和退款必须单独授权。

## 分阶段落地

1. 第一阶段：单主人账号和密码保护的 `/admin/`，凭据使用 Git 外受限文件，不建立用户表；提供匿名访客、访问会话、浏览量、来源、设备和趋势。统计从功能上线后开始，访客编号不代表真实姓名。
2. 第二阶段：留言搜索、隐藏、恢复、回复和举报；视频、尺寸资料、分类、标签、封面与上下架；图片和图纸放对象存储，数据库只留元数据。
3. 第三阶段：选择手机号或微信中的一种主登录方式；角色与权益分离；增加回复、收藏、关注和通知，私信不优先。
4. 第四阶段：先提供单项图纸、尺寸包或专题课程，再根据稳定需求增加会员。订单、支付、权益和退款分开建模；支付回调必须验签并幂等。
5. 第五阶段：每页最多一个明确标注的固定合作位，只接受与木工工具、材料、课程和展会相关的合作，不伪装成普通内容。

## 数据与合规

早期继续使用 SQLite；只有持续写锁、日活数千且互动频繁、多进程写入或复杂报表明显变慢时再评估 PostgreSQL。图片、PDF 和图纸不写入数据库。

收集手机号、支付信息或把匿名数据关联账号前，必须先完善隐私政策和用户协议。收费内容要写明交付、有效期、退款与客服；用户交流要有举报和处置流程；广告必须显著标识。数据库、上传资料和支付配置分别备份，密钥、商户证书、后台密码摘要和生产数据库永不进入 Git。
