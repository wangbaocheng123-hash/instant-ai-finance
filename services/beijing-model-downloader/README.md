# 北京模型下载器

本目录是北京采集套件中的真实模型下载器程序。它从北京服务器当前运行的
`0.8.1+login30d.05287e9f6c06` 版本做受控源码导入，只包含程序、依赖声明、服务模板和
测试；数据库、视频、图文原图、评论 JSON、浏览器登录资料、Cookie、`.env`、日志和备份均保留在
Git 外。

模型下载器与博主采集器共用当前仓库和北京生产分支，但保持独立进程、配置、数据目录、
发布判断和回滚。模型下载器全天 24 小时运行，以每轮主页检查开始时间为基准，每 3 分钟
检查一次模型先生主页；只在发现新作品时下载。该 3 分钟业务策略固定在代码中，旧环境变量
`MODEL_DOWNLOADER_INTERVAL_MINUTES` 不再覆盖它，因此部署时不需要手工修改北京 `.env`。
新作品扫描同时接受抖音 `/note/` 和 `/article/` 两种图文路由，下载具有硬优先级，期间绝不抓取评论。视频保存有声 MP4；图文作品保存完整公开
正文以及按发布顺序排列的全部 JPEG、PNG 或 WebP 原图；没有内嵌图片的 `/article/`
保存抖音公开 `origin_cover`，不生成伪图片。新下载视频在落正式库前统一转成
H.264/AAC、`yuv420p` 和网页快启 MP4；画面长宽通常各缩小约一半（例如
720×1280 → 360×640），宽度不低于 240 像素，兼顾手机封面文字和存储占用。
既有视频不在服务启动时批量重写。媒体分别存放在 Git 外的
`/srv/model-downloader/videos` 和 `/srv/model-downloader/images`。评论和手工修复只在下一次主页检查前的
空档中每次处理一项，到点强制让路；评论刷新仍按抖音实际发布时间计算：未满 24 小时每
15 分钟，达到 24 小时及以后每 60 分钟，只在成功保存后推进
`comments_collected_at`。发布器还必须在新进程启动后看到一次真实成功主页检查，不能再把
“进程处于 active”误当成采集正常。

只有所有者明确指定一条已经入库的视频时，运维端才可用精确作品 ID 执行一次源清晰度
重下：

```bash
python3 library_admin.py redownload-hd <15至22位抖音作品ID>
python3 library_admin.py hd-redownload-status <同一作品ID>
```

该命令不改变默认半尺寸策略，不接受“最新”等模糊目标。它先在同目录隐藏暂存区下载
最高画质候选，以 stream copy 生成 `+faststart` MP4，核对作品 ID、视频/音频、编码、
像素格式、分辨率严格提升及允许范围内的相同时长后才原子替换；失败恢复旧文件。同一作品
跨进程互斥，完成状态写入 Git 外 `hd_redownload_runs`，供签名桥把这类媒体修订明确标记为
`source_quality_replacement`，新加坡据此保留既有原文与关键词且不重复通知。

运行测试：

```bash
python3 -B -m unittest discover -s tests -p 'test_*.py'
```
